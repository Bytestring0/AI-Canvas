# 将军棋策略（junqi-2）

策略入口为顶层 `decide(observation)`。代码使用标准 JavaScript，同步执行，无外部依赖。每次返回至多四条移动，每条显式指定 `half`。

## 战术思路

策略采用“全局目标选路 + 局部候选评分 + 顺序模拟”。每 tick 先分析地图、威胁和经济目标，再逐条选择移动，并根据模拟结果选择下一条指令。

### 扩张与搜将

优先攻占低驻军土地，并奖励能够揭露更多未知地形的位置。攻击敌方土地还有额外收益，因为它同时削弱对方生产和领土。

从可扩张边界向己方内部传播衰减的吸引力，让闲置兵向边界汇聚。直接扩张、内部调兵和战略集结共用四条指令预算，避免只操纵最大兵团。

未知地形可以参与全局路径规划，但实际指令不会进入尚未侦察的地形格。通过占领已知边界土地扩大视野，再逐步修正路线。搜将依靠持续扩张，没有假设将军位置分布或隐藏地图信息。

### 打城与经济集结

目标选择考虑城市驻军、距离、现有机动兵、剩余时间和当前产量。中立城市需要留出回本窗口；剩余时间不足时，策略倾向保留军队。

选定目标后，从目标运行反向 Dijkstra。路径费用包括步数、估计守军和迷雾成本，使部队倾向绕开高驻军障碍。

生产点分批出兵，长途任务需要更大的出兵批次。目标附近会抑制无关扩张，使兵团有机会积累到足够攻城的规模。目标具有少量延续奖励，减少每 tick 改换方向。

### 攻击将军

发现敌方将军后，长期记录其位置和归属，并提高斩首目标的优先级。可以立即攻陷的敌方将军具有极高战术评分；对方公开军力和领土越多，击杀价值越高。

己方顺序模拟包含将军被攻陷后的可见领土转让、军队减半以及进攻剩余部队并入。模拟产生的新增己方格可供后续指令使用。

### 防守

从己方将军运行 BFS，检查附近可见敌军：

- 四步以内的敌军按可移动兵力累计，形成紧急留守需求。
- 五至八步的敌军形成较低的预警留守需求。
- 己方将军只能发出仍满足留守需求的全军或半军移动。
- 将军兵力不足时，向将军靠近的增援获得高优先级。
- 能击败将军附近敌军的攻击获得拦截奖励。

四步范围对应每 tick 最多四条指令的潜在移动距离。防守估计不扣除敌军沿途损耗，偏保守。

### 组队

使用队伍编号识别队友，不攻击队友，也不把队友领土当作己方可连续出发的中转节点。当前没有主动赠兵、联合进攻或队内角色分工。

## 迷雾与状态记忆

地形直接使用观察中已经保留的长期信息，不重复存储整张地图。

`memory` 保存：

| 字段 | 内容 |
| --- | --- |
| `v, s, w, h, me, t` | 格式版本、种子散列、地图尺寸、身份和最近 tick |
| `q` | 上次战略目标 |
| `r` | 最多 160 条重要格子的最后可见归属、军队和时间 |
| `g` | 最多 16 条敌方将军位置与身份 |
| `e` | 最近 16 条移动，用于抑制短期反向搬兵 |

记忆优先保留将军、城市和将军附近的威胁。普通敌军记录会过期；不可见城市和将军的驻军按时间保守增长，普通部队的位置可信度随时间下降。过往看到的中立驻军按不生产处理。

这些都是估计，无法推断敌方调兵。当前可见信息始终覆盖历史记录。

记忆只包含有限数字、普通对象和短数组，规模为数百个数值，不保存地图、类型化数组或路径堆，适配返回值大小限制。

## 同 tick 指令与合法性

每次选出一条指令后，立即模拟己方移动、战斗和可见领土转让，再选择下一条，因此支持连续行军和合兵。

模拟不会提前加入生产。生产发生在所有玩家指令结算之后。

对当前视野外、但地形已知的格子，可以依据历史信息尝试一次攻击；不会假设盲攻成功后继续从该格出发。未侦察地形不作为实际移动目标。

代码检查出发归属、兵力、邻接、山地及队友归属，并比较全军与半军。实际执行时，其他玩家可能先行改变局势，部分原本合理的指令仍可能被环境忽略。

## 确定性

不使用时间、网络、存储、`Math.random` 或其他非确定性来源。

同分候选通过种子散列、tick 和坐标生成固定微小扰动。堆和目标排序都有固定平局顺序。策略不依赖顶层可变状态；相同观察及记忆会产生相同输出。

## 复杂度与资源

设地图格数为 V，四邻接边数为 E，E = O(V)。

- 地图整理、威胁分析和两次 BFS：O(V)。
- 战略目标 Dijkstra：O(V log V)。
- 边界吸引力传播：使用堆和固定衰减阈值，最坏 O(V log V)。
- 四次候选扫描：O(V)；每次斩首额外扫描一次地图。
- 记忆排序：只保留重要观测，输入记录数至多 O(V)，最坏 O(V log V)。
- 总体空间复杂度：O(V)，跨 tick 记忆有固定条数上限。

扩张吸引力初值有上界，每一步固定衰减，并在低于阈值后停止传播，因此传播深度有固定上限。

实现采用类型化数组、二叉堆和固定四次行动循环，没有递归搜索、蒙特卡洛模拟或异步等待。尚未在目标浏览器和对局环境实测，不能保证所有设备都满足 200ms 限制，也不声明胜率或性能测试结果。

## 局限与设计取舍

1. 使用贪心评分，而非四步联合搜索；可能错过需要先牺牲收益才能完成的组合。
2. 每 tick 只选择一个主要战略目标，跨区域作战和多城协同较弱。
3. 迷雾驻军估计无法覆盖敌方突然合兵、撤退和增援。
4. 防守只考虑当前可见威胁，且距离忽略战斗成本；既可能过度留守，也可能漏掉视野外袭击。
5. 留守只能通过全军、半军或不动实现，无法精确发送指定数量；紧张局面下可能整队等待。
6. 同 tick 模拟采用当前观察，无法预知轮转顺序中先行动对手的具体操作。
7. 路径场在一次调用中只构建一次，后续捕获和转让不会重新规划全图，可能浪费个别行动机会。
8. 城市回本判断使用当前产量，没有精确计算未来产量分段变化；选择较保守。
9. 优先保持生存、生产和斩首机会，没有直接求解排行榜各项得分的全局最优分配。

这些取舍用于控制浏览器内计算量，同时保留扩张、集结、经济投资、搜将和紧急防守能力。
