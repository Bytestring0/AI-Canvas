# 将军棋 (junqi-2) 策略说明

strategy.js 是一个纯同步、确定性、零依赖的贪心策略:每个 tick 对全部己方格子做局部评估,
按分值选出最多 4 条移动。不做全局路径搜索、不预测对手,换取每 tick 毫秒级耗时与极强的健壮性。

## 决策流程(每 tick)

1. **知识扫描 scan**
   - 遍历 terrain/owner/army,把当前可见格子的归属与军力写入长期记忆
     (lastOwner / lastArmy / lastSeen,按格子索引 y*W+x 存放);
     terrain 由环境永久记忆,这里只同步一份 cellT 便于 O(1) 访问。
   - 见到 terrain==3 的敌方格 → 记录其将军位置 genPos[id];该玩家 alive 变 false → 清除。
2. **威胁评估 threatA**
   - 对每个己方格检查 8 邻域内**本 tick 可见**(lastSeen==tick)的敌军:
     敌军 >= 我+4 且 > 1.5x 我 → 视为受威胁。
   - 受威胁格禁止外派兵力;全局挑受威胁最重的一格,由相邻且自身不受威胁的己方格
     增援半数兵力(评分 5000−敌军,仅次于猎将)。
3. **候选与评分**(只评估 4 邻目标;己方格 4 邻必在己方 8 邻视野内,地形必然已知)

   | 目标 | 条件 | 评分 | 方式 |
   | --- | --- | --- | --- |
   | 敌方将军(存活) | floor(n/2) > 守军 | 100000 | half |
   | 防御增援 | 见上 | 5000−敌军 | half |
   | 敌方城市 | floor(n/2) > 守军+1 | 2000−守军 | half;兵力充裕(n>守军+25)时允许 all |
   | 中立城市(40~50 驻军) | floor(n/2) > 守军+1 | 1500−守军 | half |
   | 敌方普通格 | floor(n/2) > 守军+2 | 500 | half;或 all(n−1),留缓冲 |
   | 中立空地 | floor(n/2) > 0 | 200+min(n,60) | half |

   - 所有进攻都要求留 1~2 军余量,拒绝 1:1 消耗;己方将军格永不 all 出击,
     己方城市 all 攻击要求保留 >=25 军缓冲;最后 150 tick 禁用 all(n−1) 冒险进攻。
4. **选择**
   - 评分降序(稳定排序 + 固定遍历顺序 → 完全确定),同一出发格只取一条,最多 4 条。
   - **扩张链**:若某条"推入中立空地"被选中且出发格兵力 >=8,追加一条从刚占领格
     再推一步的指令,利用"同一 tick 内前一指令结果对后续可见"的规则,一 tick 前进两格。
5. **兜底**:decide 整体 try/catch,任何异常返回 {moves:[]} —— 格式合法,
   绝不因 bug 被判策略错误出局(代价只是待命一 tick)。

## 状态记忆

- 状态全部放在 **Worker 顶层变量**(协议明确允许跨 tick 保留),不占用 memory 的
  32768 字符上限;memory 恒返回 null。每局 Worker 独立初始化,且 tick===0 时强制重建状态。
- 记忆内容:
  - lastOwner / lastArmy / lastSeen:所有曾见格子的最后归属、军力、tick。
    威胁判断只信任本 tick 可见的新鲜数据,避免用过时军力误判。
  - genPos:见过的敌方将军格。即使离开视野仍保留 —— 这是"猎将"评分的依据,
    对应 1500x击杀/敌方玩家数 以及对方整片领土(军队减半)转让的收益。
  - wO / wA:本 tick 规划用工作副本(同队格归一为我方,供扩张链使用)。
- 确定性:不用 Math.random / Date / performance / crypto;遍历顺序固定、
  稳定排序、全部严格不等号比较 —— 同种子、同名单、同脚本必然复现。

## 复杂度

- 时间:每 tick O(W*H + 12*M),M 为己方格数。最大辽阔图 168x164 ≈ 27.5k 格,
  估算 < 10ms,远低于 200ms 上限。
- 空间:6 个 TypedArray 共约 17 字节/格(≈470KB @ 27.5k 格),另有 O(M) 候选数组。
- 返回:<=4 条移动,JSON 远小于 32768 字符,全部为有限整数,无循环引用。

## 战术思路(与评分项对应)

- **领土 + 军力份额(2000+2000)**:扩张常开,每 tick 用前沿格推中立空地;
  半兵制扩张(留一半在原格)保持纵深;占中立城市拿产量。
- **击杀(1500/敌方玩家数)**:猎将最高优先,只要见过的敌方将军守军被 floor(n/2) 压制就出击;
  歼将后对方全部领土军队减半归我,是滚雪球的关键事件。
- **城市**:敌方城市评分高于普通格 —— 攻下既减其产量又增我产量,双向收益。
- **防守**:威胁阈值触发"禁出 + 增援",防偷家;进攻留余量,不打无把握的仗。
- **迷雾利用**:地形永久记忆 + 将军位置记忆 + 新鲜/陈旧数据区分;
  己方格 4 邻必可见,因此不存在盲走山地。

## 局限

1. 无路径搜索:只对 4 邻目标做局部贪心,不能规划绕开敌区的长距离机动;猎将依赖"先走到将军旁边"。
2. 不预测对手:假设目标格守军静止,同 tick 被第三方抢先或反扑时可能误判(损失有限,余量可吸收)。
3. 无多格协同攻坚:不组织多个相邻格同 tick 叠加兵力打重兵目标。
4. 组队模式只把队友格视为可增援目标,不主动支援被攻击的队友,也不与队友交换情报。
5. 威胁只看 8 邻:2~3 格外快速逼近的敌军来不及反应(依赖生产增速追赶)。
6. 未见过的中立城市/敌方格不冒进,扩张偏保守。
7. 末段(tick > maxTicks−150)全面保守,可能错失最后翻盘窗口。

## 设计取舍

- **贪心 vs 搜索**:200ms/tick 且"推荐同步快速算法",放弃 BFS/模拟前瞻,换取零超时风险与可审计的确定性。
- **保守余量 vs 冒进**:进攻一律留余量,宁可少占地也不 1:1 换军 —— 军队总量占 2000 分,且是一切后续进攻的本钱。
- **顶层状态 vs memory**:memory 有 32768 字符上限且要 JSON 序列化,顶层 TypedArray 更快更省;
  协议明确允许,且每局 Worker 全新,无跨局污染。
- **异常兜底**:宁可待命也不出非法格式 —— 策略错误出局总分直接为 0,是最坏结果。
