# 将军棋策略 junqi-2：说明文档

本文档只描述算法设计，不包含任何实测胜率或排名数据。我没有运行过这份代码。

## 1. 总体思路

策略是"一个主力大军团 + 若干小股扩张 + 其余兵力汇聚"的启发式框架。每 tick 最多输出 4 条指令，分配顺序如下：

1. **A. 机会性攻占**：任何己方格子（军队≥2）相邻的敌方或中立城市格，只要 `军队-1 > 守军` 就攻占。攻陷敌将军优先级最高，且不占用名额上限。普通攻占最多用 2 个名额。
2. **B. 主力任务**：主力是全图军队最多的己方格子。按优先级选一个任务，沿距离场前进一步。
3. **C. 小股扩张**：军队在 2~12 的非主力格子，就近吞并相邻中立空地，最多 2 步。
4. **D. 汇聚**：剩余名额让其他大股部队沿己方领土向集结点靠拢。集结点通常是主力，防守时是将军。

主力任务优先级如下：

| 优先级 | 任务 | 触发条件 |
| --- | --- | --- |
| 1 | 防守 | 将军 7 步内有当前可见的强敌，且其军队 ≥ 己方将军军队的 2/3，同时 ≥3。主力能赢则攻击该敌，否则全军回守将军（guard）。 |
| 2 | 斩首 | 已知敌方将军，且主力军队 ≥ 估计守军×1.25 + 6 + 0.3×路程。 |
| 3 | 打城 | 70 步内存在已知中立城市，且主力军队 ≥ 驻军+3。取最近的一座。 |
| 4 | 袭扰 | 14 步内存在比主力弱的已知敌格。 |
| 5 | 扩张 / 探索 | 主力沿"中立空地 + 未知迷雾"的多源距离场前进，类似蛇形扩张。每步只在身后留 1 兵，其余随头部走。未发现敌将军时一直探索。已知敌将军但打不动时，仅当前沿在 8 步内才扩张，否则 hold。 |
| 6 | hold | 主力原地不动，其他兵力汇聚过来积累。 |

## 2. 关键实现

- **移动模拟**：每条指令都在本地副本上结算，后续指令基于更新后的状态。这与规则"同 tick 内前一指令的结果对后续可见"一致。
- **拒绝必败进攻**：`mv` 在 `k <= 守军` 时直接拒绝，不会白送兵力。
- **多源 BFS 距离场**：任务目标可以是一个格子，也可以是一组格子，如所有未知或中立格、所有较弱敌格。部队只需沿距离下降方向选邻格。选格时优先能攻占的格子，其次才是己方格子。
- **蛇形扩张**：向兵力为 0 的中立空地移动时，全部 `n-1` 兵都会占领新格，原格只留 1 兵。因此兵力几乎不损耗，土地数递增。
- **将军估计**：敌将军位置从永久记住的 `terrain===3` 读出。其军队数取最近一次可见值，不可见时加上 `min(0.7·g·经过tick数, 250)` 的保守增长估计。从未见过其军队数时按 40 兵起算。
- **团队**：用 `players[].team` 区分友军，友军格视为可增援，不会被攻击。已出局玩家的记忆格视为中立。
- **回合末**：不特殊处理。因为不做必败进攻，兵力总量只会因被攻击而减少。

## 3. 状态记忆

- 顶层变量 `S` 保存与地图等大的 `ownM`、`armM`、`seen`：每格最后一次可见时的归属、军队数和看到的 tick。用于在迷雾外回忆城市驻军、敌将军军队数和敌方领土。`seed` 改变或 tick 回退时重置，保证每局独立。
- 返回的 `memory` 只有 `{v, seed, m}`，约几十字节，远低于 32768 字符。它只用于调试，决策不依赖它，因为全部有用信息都能从 `observation` 与 `S` 中重建。
- 全程不使用 `Date`、`Math.random` 等非确定性输入，没有随机数。所有排序都有确定的次序键，相同种子和对手脚本应可重赛复现。

## 4. 复杂度

设 N = 宽×高。最大约 (40+8·16)×(36+8·16) ≈ 27,500 格。

- 每 tick 有若干次 O(N) 扫描和最多约 6 次 BFS（防守、主力距离、任务场、扩张场、汇聚场等），总计 O(N)，常数约 10~15。
- 候选排序是 O(M log M)，M 为候选数，远小于 N。
- 内存为 O(N)，每 tick 临时分配若干 Int32Array。
- 同步执行，没有异步等待。我没有测量实际耗时，仅凭复杂度估计应远低于 200ms 限制。外层 `try/catch` 保证异常时返回空指令而非判错出局。

## 5. 局限

- **单主力**：同一时刻只有一个主力军团。面对多路夹击、多方混战时，防守和进攻能力有限。
- **不做对手建模**：不识别对手风格、不预测对手行动，也不利用"双方同 tick 互攻将军"的先后手细节。
- **路径代价不加权**：BFS 视所有可通行格代价为 1，不绕开高驻军格或敌方重兵区，只靠"不可攻占则换邻格"来规避。
- **敌将军位置估计粗糙**：对敌军队数的外推是保守启发式，可能高估或低估。
- **组队**：只做了"友军格可增援、不攻击"，没有协同战术，如与队友会师或交换情报。
- **汇聚代价**：汇聚阶段每 tick 最多 4 步，大领土上军队汇集较慢。
- **迷雾记忆会过时**：记忆的敌方归属和军队数可能已变化，会导致袭扰或斩首判断失误。
- **不处理的情况**：不处理最后阶段的"以军力判胜"博弈，如囤兵到回合结束。

## 6. 设计取舍

- 选择"规则 + 距离场"而非搜索或模拟：搜索在 4 步/tick、多人迷雾的环境下分支太大，且 200ms 预算紧张。
- 宁可保守也不白送兵力：军队总量既是胜负判据，也占军力分，所以"必败不打"。
- 扩张优先于囤兵：领土分和产兵都与地盘挂钩，早期快速铺开收益高。
- 小股与主力分工：小股负责铺地，主力保持完整以便打城和斩首，避免兵力被零散消耗。
- 本说明不声称任何实测结果。参数如 1.25、6、0.3、阈值 7 和 14 都是经验设定，未经调优。
