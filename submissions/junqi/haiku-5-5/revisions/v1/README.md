# README — 将军棋策略 junqi-2

## 概览

本策略是一个确定性的启发式策略，每个 tick 只做一次 O(W·H) 的全图扫描与至多一次 BFS，
不依赖任何非确定性输入（Date、Math.random 等）。随机性仅通过由 `seed` 与 `tick` 派生的
mulberry32 伪随机数生成器引入，用于打破同分候选之间的平局，因此同一地图种子与对手脚本下可复现。

## 算法结构

1. **感知**：扫描当前视野，收集己方格子、可见敌方格子与可见敌方将军。
2. **记忆**：`memory` 中保存已发现的敌方将军坐标。将军地形在迷雾中会被记住，因此即便敌方将军
   当前不在视野内，仍可作为攻击目标。若该格地形不再是将军（已被攻陷），则从记忆中移除。
3. **防守**：若视野内有兵力较强的敌军靠近己方将军（曼哈顿距离 ≤ 4），则暂停向外发兵，
   让将军附近兵力不足 6 的格子留守，以积累防御力量。
4. **进攻**：
   - 已知敌将军时，以多源 BFS 计算所有可通行格子到敌将军的距离场，每个己方格子沿距离
     递减方向移动（`half: true`，保留一半守军）。
   - 未知敌将军时，优先攻击相邻且可击败的敌方/中立格；空地加分以鼓励扩张，城市略次之。
     判定"可击败"时要求 `floor(军力/2) > 守军`。
   - 无攻击机会时，向未侦察区域（地形为 -1）的距离场移动，用于搜索敌将军。
5. **输出**：按军力从大到小遍历己方格子，每 tick 最多输出 4 条移动，且同一格子不重复出发。

## 状态记忆

`memory` 仅包含 `knownEnemyGenerals`（已见敌将军坐标列表）、`lastTick` 等小型字段，
大小远小于 32768 字符上限，且全部为可 JSON 序列化的普通对象。

## 复杂度

- 每 tick 全图扫描：O(W·H)。
- 每次 BFS：O(W·H)，每 tick 至多两次（攻将军距离场与搜索距离场）。
- 地图最大为辽阔场地 16 人时约 (40+128)×(36+128) ≈ 27,000 格，单次 tick 运算量仍在百毫秒以内的合理范围，
  但具体耗时未经实测，不作承诺。
- 空间：O(W·H) 的临时数组，不随 tick 增长。

## 局限

- 未对敌方兵力做概率推断，只依据当前视野内的数值。
- 防守规则较粗糙：仅依据曼哈顿距离与军力阈值，未考虑多方向来袭。
- 搜索策略是"向最近未知格"推进，没有利用敌方将军通常远离自身这一先验。
- 未处理增援链：每条指令独立决策，没有显式协调多个军团同时进攻同一目标。
- 城市与中立格的战斗收益未做精细的期望计算。
- 同队判断依赖 `players` 数组中的 `team` 字段，若队伍信息缺失则退化为仅识别自己。
- 没有实测数据，上述策略的实际胜率与性能需在真实对局中验证。

## 设计取舍

- **确定性优先**：所有随机性由种子派生，牺牲了一部分探索多样性，换取可复现性。
- **简单性优先**：避免复杂的评估函数与多步前瞻，以保证每次决策远低于 200ms 的时限。
- **半量移动**：默认使用 `half: true`，既保留守军，也能让大部队逐步向外分散，减少被一击清空的风险。
- **记忆最小化**：只保存必要的敌将军坐标，避免 memory 膨胀导致序列化开销。
