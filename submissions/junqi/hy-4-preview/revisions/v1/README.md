# 将军棋策略（协议 junqi-2）

交付物：

| 文件          | 说明                                                                                                                              |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `strategy.js` | 策略本体，顶层定义 `function decide(observation)`。纯同步 ES5 风格 JavaScript，无 `import` / `export` / 第三方包 / 外部文件依赖。 |
| `README.md`   | 本文档：算法、状态记忆、复杂度、局限与设计取舍。                                                                                  |

---

## 1. 总览

策略的核心是一&#x4E2A;**"势场 + 贪心 + 同 tick 模拟"**&#x7684;确定性决策器，每 tick 走一遍下面五步：

1. **重建信念地图**：把 `observation` 的当前可见信息，与策略自己长期记住的"最后一次看到"的信息合并，得到一张对全图（含迷雾区）的估计。
2. **算 5 张 BFS 距离势场**：未知区域、中立/敌方城市、敌方将军（含疑似位置）、敌方领土、己方将军。它们充当"战略引力"。
3. **算将军守军下限**：扫描将军周围 3 步内的敌情，决定本 tick 至少要留多少兵守家。
4. **贪心挑 4 条指令**：每一条都在**内部模拟棋盘**上即时结算，再基于新棋盘挑下一条，因此天然支持"同一 tick 内一支纵队连走 4 格 / 连占 4 格"。
5. **出口校验**：过滤非法指令，保证任何异常都退化成"不动"，绝不因格式问题出局。

设计上刻意放弃了博弈树搜索：在 200 ms、每 tick 4 条指令、迷雾极大的约束下，搜索的收益远不如"把估值函数做对 + 把集结/奔袭的时序做对"。

## 2. 状态记忆

### 2.1 分三层

| 层     | 载体                               | 内容                                                                                                             | 为什么这样放                                                           |
| ------ | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 免费层 | `observation.terrain`              | 地形（山地/城市/将军位置一旦侦察永久保留）                                                                       | 协议已保证，不必自己存                                                 |
| 主层   | Worker 顶层 `Int8Array/Int32Array` | `lastOwn`（最后看到的归属）、`lastArm`（最后看到的兵力）、`lastSeen`（看到的 tick）、`genList`（已知敌方将军格） | 协议允许顶层变量跨决策保留；全图级别的记忆无法塞进 32768 字符的 memory |
| 兜底层 | 返回值里的 `memory`                | 已知敌方将军（格子 + 归属）、已侦察城市的驻军、最多 420 个敌方格的最后观测                                       | 万一 Worker 被重建，用 `o.memory` 恢复关键知识；体积受硬编码上限约束   |

`memory` 的结构是紧凑的扁平数字数组（`g` 将军、`c` 城市、`e` 敌方格），不是二维表，避免 JSON 膨胀。实测（自建引擎，168×164 / 16 人地图）每次返回的 JSON 在 2 KB 量级，远低于 32768 上限。

**重开一局的判定**：种子、宽高、自身 id 任一变化，或 `tick` 归零 / 回退，就重新分配缓冲区并尝试从 `memory` 恢复。同一 Worker 内若被要求服务多个玩家（协议说不会，但做了防御），每次 `o.you.id` 变化也会重置并从该玩家自己的 `memory` 恢复，逻辑仍然自洽，只是丢掉一部分细节记忆。

### 2.2 迷雾外的推断

对当前不可见的格子，用"最后一次观测 + 生产"外推，**不做任何随机猜测**：

```
将军格：  lastArmy + floor(g * dt * 0.5)     // 将军常被调兵出去，打折
城市：    lastArmy + floor(g * dt * 0.6)
普通土地：lastArmy + floor(g * dt / 25)
中立格：  不再增长，直接沿用
```

其中 `g = 1 + floor(tick/200)`，`dt = tick - lastSeen`，单格增长量封顶 250。  
另外用公开信息做一次硬约束：**单格兵力不可能超过该玩家的公开总兵力**（`players[i].army`），超出即截断。

从未见过的格子：按地形猜——空地视为 0 兵中立，城市视为 45 兵中立（40~50 的中值），山地不可进入。

这套外推只用于"要不要打/要不要防"的下界判断，绝不用于精确计算。任何真实战斗决策都以**当前可见**的 `owner/army` 为准。

## 3. 势场（战略引力）

每 tick 做 5 次多源 BFS（4 邻接，已确认的山地作为墙），各得到一张距离场：

| 场   | 源                           | 用途                                       |
| ---- | ---------------------------- | ------------------------------------------ |
| `FH` | 己方将军                     | 回防方向；同时也是"反推敌方将军方位"的尺子 |
| `FU` | 所有 `terrain === -1` 的格子 | 探索：把部队推向迷雾                       |
| `FC` | 所有不属于我方/队友的城市    | 抢城（中立城和敌方城都算）                 |
| `FG` | 已知敌方将军 + 疑似敌方将军  | 猎杀主引力                                 |
| `FE` | 所有敌方格                   | 压迫敌方领土、往纵深打                     |

移动的价值里包含"势能下降量" `drop(F, from, to) = F[from] - F[to]`（不可达记 0）。**注意：正交邻居永远在我的 8 邻域视野内**，所以第一步的目标格归属与兵力一定是精确的；只有连锁第二、三步才可能碰到迷雾，对此有专门的不确定性惩罚。

### 3.1 如何在没看见敌方将军时也找得到它

将军初始位置彼此远离（协议保证）。因此对"还没见过将军的敌方玩家"，策略把他**已知格子中 `FH` 最大者**（离我方将军最远的那一格）当作疑似将军，放进 `FG` 的源里。部队会被吸向敌方纵深，打进去之后视野一开就会看到真正的将军，随后 `genList` 接管。

一旦某格地形不再是将军（被攻陷后变城市），对应记录会被清理。

## 4. 决策：贪心 + 同 tick 模拟

```
simOwn ← OW ; simArm ← AR
repeat 4 times:
    best ← argmax over (出发点 f, 方向 d, 模式 m) of score(f, d, m)
    if best 不存在或分数 < 阈值: break
    把 best 作用到 simOwn / simArm        // 同 tick 内后续指令能看到结果
    记录这条指令
```

- **出发点集合** `S`：己方兵力 ≥ 2 的格子。数量超过上限时，取"兵力最大的 480 个 + 前线格抽样 220 个"（外加将军本身）。这一步很关键——早期踩过坑：按数组下标等距抽样会把最大的那支纵队排除掉，导致全军永远无法集结。
- **模式** `m`：`half:true`（走 `floor(n/2)`）与 `half:false`（走 `n-1`）都评估，取分高者。
- 只有期望收益 > 阈值（`THRESH = 0.5`）才行动；没有正收益就原地不动，让兵力自然增长。

### 4.1 估值函数

一次移动 `f → t`，带兵 `k`，记：

```
flowX = WU·drop(FU) + WC·drop(FC) + WCE·(向地图中心靠近量)     // 扩张型引力
flowE = WG·drop(FG) + WE·drop(FE)                              // 攻势型引力
amp   = 1 + min(k, 60)/15            ∈ [1, 5]                  // 兵越多，越该由它去执行攻势
prog  = flowX + flowE · amp
```

**内部调动**（目标是自己的格子）——只有真的在靠近目标或正在回防才值得走：

```
val = prog + 回防奖励 + 推进奖励
回防奖励 = DEF_W · min(k, 将军缺额) · (直接进入将军 ? 2 : 1)     // 只在 drop(FH) > 0 时给
```

**战斗**（目标是中立/敌方格）——必须严格 `k > 守军`，否则这条候选直接否掉（绝不送兵）：

```
gain = W_KILL                           敌方将军
     | cityVal + 夺城奖励                城市（cityVal = min(剩余回合, 600) · g · 0.4）
     | W_ENEMY_LAND + deny · 守军        敌方土地（deny 依我方/敌方总兵力对比取 0.9 或 0.15）
     | landW                             中立空地

val = gain − costW · 守军 + prog + 推进奖励
      + visW · (目标格周围未探索格数)        // 反迷雾收益
      − MTN_PEN · (目标格周围已知山地数)     // 避开死路
      − UNCERT_PEN                          // 目标格信息不确定（迷雾外/地形未知）
      + CHAIN_W                             // 本 tick 内继续推进同一支纵队
      − RESERVE_PEN · 缺额                  // 从将军出兵导致守军低于下限
```

几个刻意的设计点：

- **`amp`（攻势放大）**：`flowE` 按带兵量放大到 5 倍。效果是"大垛去奔袭，小垛去捡地"，避免几百个小垛各挪一格、谁也走不到前线。
- **`CHAIN_W`（连锁奖励）**：同一 tick 内，从刚被移动到的格子继续走会额外加分。这让 4 条指令合成一支纵队的 4 格推进（一路吸收沿途己方格子），而不是 4 支互不相干的部队各走 1 格。这是"能否集结出决定性一击"的关键开关。
- **`costW`（消耗战代价随实力对比缩放）**：碾压对手时（我方总兵力 ≥ 对方 3 倍）把军队损失的成本降到 0.45 倍；劣势时抬到 1.6 倍。否则"为了打到将军必须先啃掉一个 2900 兵的敌方格"这种必要消耗会被估值函数否掉。
- **中立空地是零成本的**：`k > 0` 即占领且 `k − 0 = k`，军队守恒，所以只要还有空地就永远值得占。

### 4.2 参数随局势切换

| 条件                           | 调整                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------- |
| `tick < 120`                   | 探索权重 `WU` 拉到 1.8（前期视野 = 一切）                                        |
| 剩余回合 > 60                  | 城市引力 `WC = 2.2`；否则归零（快结束了砸 45 兵换一座城是亏的）                  |
| 我方 ≥ 最强敌人 2 倍且已知敌将 | `WG = 6.5`、`WE = 2.0`，并进入**清场模式**：把捡地收益压到 30%、探索权重压到 40% |
| 我方 ≥ 最强敌人 1.3 倍         | `WG = 4.0`、`WE = 1.5`                                                           |
| 落后且剩余 < 120               | `WE = 1.6`（必须抢军力/领土才能翻盘）                                            |
| 剩余 < 25                      | `WG = 1.0`（来不及奔袭，专心抢地抢兵）                                           |

清场模式的理由来自计分表：胜利 4000 分 + 每个击杀最多 1500 分，而"多占一格地"在领土已经压倒性时的边际收益不到 1 分。不主动切换的话，部队会一直被"眼前还有空地可捡"勾住，永远清不完场。

## 5. 将军防守

1. **威胁扫描**：从将军做 BFS，扫 3 步内的敌方格，估算"最多能送到多少兵" `≈ 兵力 − 步数`（对手每步最多损失 1 兵）。迷雾外的敌情按 0.6 折计——既不无视潜伏威胁，也不被过期记忆吓得全员回防。
2. **守军下限** `need = max(威胁 + 1, 基础守军)`，基础守军随家底变厚从 1 → 6 → 12 → 20，保证将军不会空城。
3. **回防**：若将军兵力低于下限，任何"朝将军方向"的调动都会拿到 `DEF_W × 输送量` 的奖励，直接进将军格再翻倍。
4. **禁止掏空**：从将军出兵若会让守军跌破下限，按缺额扣 `RESERVE_PEN`。

## 6. 复杂度

设 `A = W × H`（最大 168×164 ≈ 27.6 k），`S` 为候选出发点数（≤ 700）。

| 阶段                            | 复杂度                                 | 说明                          |
| ------------------------------- | -------------------------------------- | ----------------------------- |
| 信念地图重建                    | O(A)                                   | 一次全图扫描                  |
| 邻域统计（迷雾收益 / 死路惩罚） | O(A)                                   | 只对未知格与山地格展开 8 邻域 |
| 5 次 BFS                        | 5 × O(A)                               | 每格最多入队一次              |
| 将军威胁扫描                    | O(A)                                   | 复用 `FH`                     |
| 候选出发点收集 + 排序           | O(A + S log S)                         | 仅在超过上限时才排序          |
| 贪心 4 步                       | O(4 × S × 4 方向 × 2 模式) ≈ O(S)      | 常数约 32 倍，S ≤ 700         |
| 合计                            | **O(A + S log S)**，约 10·A 次基本操作 | 与玩家数无关                  |

内存：约 15 个 `A` 长度的 TypedArray（最大地图约 1.5 MB），全部一次性分配、逐 tick 复用（`.fill()` 而非重新 `new`），避免 GC 抖动。

实测耗时（见第 9 节的自建引擎）：168×164 / 16 人地图上中位数约 6 ms、p99 约 12 ms；标准场地（≤ 64×62）中位数 0.4~1.1 ms。均远低于 200 ms 上限。

## 7. 合规性

- 顶层 `function decide(observation)`，返回 `{ moves, memory }`。
- 无 `import` / `export` / `require` / `importScripts` / 动态模块；无 DOM、`window`、`self`、网络、存储调用。
- 不使用 `Date`、`performance`、`Math.random`、`crypto`；**没有任何随机源**，同种子 + 同脚本必然复现（已在本地验证：同一场比赛跑两遍，逐 tick 结果完全一致）。播放速度不影响决策。
- 返回的所有数字都是有限数，无 `BigInt`、无循环引用；`memory` 为扁平数字数组。
- 出口做了二次校验：坐标取整校验、`dir` 白名单、条数 ≤ 4、异常兜底为 `{moves: []}`。
- 文件约 22 KB，远低于 100000 字节上限。

## 8. 局限与取舍（明确写出来）

1. **不做博弈搜索**。没有 minimax / MCTS，不预测对手这一 tick 会怎么走。代价是同 tick 抢格子、以及"对手刚好在我出兵后打我将军"这类情形只能靠保守的守军下限兜底。换来的收益是每帧几毫秒、行为可预测。
2. **单步贪心，不是最优分配**。4 条指令是逐个挑的，不是对 4 条指令的组合做优化。理论上存在"换一种组合更好"的情形。
3. **候选出发点有上限**。己方格子数超过 700 时会按"兵力最大 + 前线抽样"截断，深处的小垛那一 tick 分不到指令。实际上影响很小（它们兵力低、产出慢），但确实不是完备搜索。
4. **迷雾外的兵力只是下界估计**。策略无法知道对手把兵调走了还是堆起来了；因此它倾向于"看得见的才打"，这会让它在对手龟缩时偏保守。
5. **疑似将军推断是启发式**。"离我方将军最远的敌方格"在对手领土被切分成两块、或对手已经搬家时会指错方向。此时部队会打进错误的一侧，靠后续视野修正。
6. **不做欺骗与协同**。没有佯攻、没有多线并进（4 条指令基本都给了同一支纵队）、没有和队友的战术配合；组队模式只做到"识别队友、不攻击队友、不主动送兵"。
7. **城市价值用线性折现**（`min(剩余, 600)·g·0.4`），忽略了"对手也会来抢""拿了城要守"等二阶效应。
8. **参数靠人工设定**，没有做过离线大规模对局调优；权重之间的相对量级是基于计分表和量纲分析推出来的，不是拟合出来的。
9. **不做对手建模**（协议禁止得知对手身份与源码），所有对手都被当成同一类威胁。

## 9. 本地验证（自检用，非平台实测）

为了让"不崩、输出合法、耗时可控、可复现"这几件事有据可依，我在本地另写了一个**简化的 junqi-2 引擎**（严格按协议第 3~8 条的结算顺序实现）和两类基线对手，跑了三组检查。需要强调：**这是我的自建引擎，对手是规则型基线机器人，结果只用于定性自检，不代表平台线上的真实战绩。**

- **对基线机器人**：紧凑 2 人 / 4 人、标准 2 人 / 4 人场次分别在 164 / 272 / 312 / 545 tick 清场获胜；标准 8 人场拿到 6/7 次击杀；辽阔 16 人场未能清场（地图过大、4 条指令/tick 探索不完），但以压倒性的兵力与领土在回合用尽时判胜。
- **自对弈**（双方都用本策略）：2 人场 1200 tick 内无人阵亡，但一方以约 5 倍兵力、4.5 倍领土压倒；4 人场势均力敌、无人阵亡；8 人场淘汰 4 人。全程无异常、无超时。
- **边界输入**：阵亡、全图被山地包围、将军只有 1 兵、`tick = 0`、`maxTicks = 0`、最后一 tick、地形全未知、`players` 为空、16 人、组队模式、`memory` 为脏数据/字符串、`owner/army` 缺行、3×3 极小地图——共 15 项，全部返回合法结果且不抛异常。
- **确定性**：同种子连跑两场，逐 tick 状态完全一致。

## 10. 参数表（便于调整）

集中在 `strategy.js` 顶部：

```
W_LAND=20        占中立空地        W_ENEMY_LAND=30   占敌方土地
W_CITY_EXTRA=100 从敌方手里夺城     W_KILL=6000       攻陷敌方将军
ARMY_COST=1.1    每损失 1 军的代价  W_MOVE=0.02       推进奖励（兼大垛优先）
MOVE_CAP=500     CHAIN_W=7         同 tick 连锁推进
W_VIS=2.0        每揭开 1 格迷雾   MTN_PEN=1.2       死路惩罚
UNCERT_PEN=2     迷雾外不确定惩罚  THRESH=0.5        行动阈值
DEF_W=5          回防每兵价值      RESERVE_PEN=12    掏空将军惩罚
SRC_LIMIT=480    大垛候选上限      INNER_LIMIT=220   前线候选上限
AMP_CAP=60 / AMP_DIV=15           攻势放大系数
CITY_GUESS=45    未见中立城市的默认驻军
```
