# 将军棋 junqi-2 策略 —— "Surveyor"

单文件、零依赖、完全确定性的将军棋（generals.io 类玩法）策略。
核心思路：**用顶层变量维护一张"信念地图"，在迷雾下持续估计每格归属与兵力；用一个带优先级的任务机驱动主力兵团（防守 → 斩首/夺城 → 前沿磨地 → 回家补给），剩余编制做捡漏、骚扰与收拢。**

---

## 1. 总体架构

每个 `decide(observation)` 调用分四层：

1. **知识层**：把本 tick 视野内格子的 `owner / army` 写入持久记忆，并维护己侦察地形、敌将登记表、首次目击时刻。
2. **评估层**：由记忆生成"信念地图"（视野外按增长率外推敌方兵力），计算将军 BFS 距离场、敌方大部队危险图、队伍军力排名。
3. **决策层**：先做威胁评估（是否有敌大部队逼近将军），危险则进入防御子流程；否则按优先级为主力兵团选任务，并沿路径发出最多 4 条链式移动（带虚拟结算）。
4. **编制层**：用剩余的移动配额让其他兵团捡漏（占邻格空地）、骚扰弱敌、参与磨地或收拢回家。

文件末尾有一段**初始化期预热**：脚本加载时用一张 10×10 的假局面调用 `decide` 约 24 次，把热路径 JIT 编译完。协议给每个 Worker 最多 1500ms 初始化预算，而单次 decide 只有 200ms——把首几次调用的编译开销挪到初始化阶段，避免冷启动尖峰导致超时出局。

## 2. 状态记忆（顶层变量，跨 tick 保留）

协议允许顶层变量跨决策保留，且 Worker 每局独立初始化，因此全部长期状态放在顶层对象 `S` 中，全部使用 TypedArray，规模 O(宽×高)：

| 字段 | 含义 |
| --- | --- |
| `kOwner / kArmy / kTick` | 每格最后一次可见时的归属 / 兵力 / tick（视野快照） |
| `terrF` | 本 tick 地形扁平缓存（环境自身会持久化已侦察地形，直接采用） |
| `bOwn / bArm / bVis` | 信念地图：当前归属 / 估计兵力 / 是否可见 |
| `fTick` | 每格**首次**目击时刻（推断敌方腹地用） |
| `gens / genKnown` | 已知敌将位置 → 归属（`-3` 为队友将军，永不攻击） |
| `guess` | 各敌方玩家的"腹地格"：该玩家所有已见格子中**最早目击**的那格 |
| `danger` | 可见敌大部队（≥10 兵）的 8 邻域强度图 |
| `homeDist` | 从己方将军出发的全图 BFS 距离场（回防、回家共用） |
| `teams / aliveP / pArmy / pLand / teamArmy` | 全员公开信息（队伍、存活、总军力、总领土） |
| `plan` | 当前任务 `{task, target, since}`，提供目标黏滞防止抖动 |
| `rng` | mulberry32 状态，由 `seed + you.id` 哈希驱动 |

**迷雾利用的三条主要途径：**

- **信念外推**：视野外的敌方格子按 `兵力 + Δt × g × rate` 增长估计（城/将 `rate=1`，普通地 `0.3`），作为进攻代价与交战决策的依据；对超过 3 tick 未刷新的情报，链式移动要求 `k ≥ 守军×1.5 + 4` 的额外冗余。
- **腹地推断**：一名玩家的领土是从将军向外扩张的，因此**我们最早看到的那格敌方土地大概率靠近其将军**。对从未目击将军的敌人，把其腹地格作为价值 80 的进攻目标——进攻路径穿过其领土时视野随之展开，通常会先目击真正的将军（terrain=3，环境会永久标记），随后自动切换成斩首任务。
- **将军登记**：`terrain=3` 的格子一旦可见就记录归属；队友将军标 `-3` 永不攻击；已陷落（重新可见时地形不再是 3）的记录会被清除。

每次返回 `memory: null`：既然规范保证顶层变量跨 tick 保留，就没有必要把状态塞进受 32768 字符限制的 memory 里再解析回来（大地图整图快照根本放不下）。跨局污染用 `seed|id|尺寸|人数|maxTicks` 组成的 key 检测，不一致即整体重置。

## 3. 每 tick 决策流程

```
decide(o):
  ensureState / 更新知识 / 信念 / 危险图 / 腹地推断 / 宏观排名
  homeDist ← BFS(将军)
  stacks ← 己方 army≥2 的格子, 按兵力降序          (己方格永远可见)
  threat ← computeThreat()                          (将军 16 格半径内的敌大部队)
  if threat.danger: 防御子流程; 否则:
      runPrimary()   主力任务机
      runExtras()    剩余编制
  sanitize() 结构校验后返回 {moves, memory:null}
  整个函数包在 try/catch 里, 任何异常返回空 moves     (防"执行异常出局")
```

### 3.1 主力任务机（优先级从高到低）

1. **斩首 / 夺城**（`findOffense`）：从主力位置跑一次 Dijkstra 代价场，进入每格的代价按"打下来的成本"计价（己方格 0.35、队友 0.6、中立空地 1、未知 2.5、敌地 `2.5+兵力×1.4`、城/将 `4+兵力×1.7`、中立城 75；邻接敌大部队的格子代价 ×6 绕行）。候选目标与价值：
   - 已知敌将：135 + 弱者加成（总军力越低越值得打，击杀可接收其全部领土）；
   - 敌方城市：45；中立城市：随剩余 tick 折算（≤52，驻军 >55 的不碰）；
   - 敌方腹地格：80（仅当其将军位置未知）。
   - 评分 `价值 − 1.1×(距离 − 进入目标格自身代价)`，可行条件 `兵力 ≥ 路径代价 + 2`。早期（t<30）门槛抬高到 55（只捡超便宜的目标），比赛末期按排名调整：落后则降到 −25 搏命，领先求稳则抬到 60。
2. **前沿磨地**（`findFrontier`）：同一套代价场，目标改为三类格子——中立空地（30）、未知格（26，侦察）、敌方土地（24，"吞地"）。这是中后期的主引擎：**大兵团碾进敌占区，每一步进格都是一次占领**（敌方 1 兵格的成本仅 ~4 兵），同时危险图让路径自动避开敌方大部队。吞地仅在敌队总军力 ≤ 我方 1.5 倍时启用。
3. **回家补给**（`HOME`）：主力 ≤3 兵、或磨地无目标时，沿 `homeDist` 下山回将军，沿途把散落的 1 兵收编，与将军堆合并后再次出征。

任务选择有一层**守家底线**（`guardFloor`）：估计敌方能组成的最大兵团 ≈ max(可见最大敌堆 ×0.8, 敌方最强队伍总军力 ×0.1)，且不超过我方总军力一半。将军堆低于底线时留守攒兵，超过底线且明显大于野战兵团（×1.3）时才以**半军出征**（第一条移动 `half:true`）——出征的一半去磨地/进攻，留下的一半守家，避免"倾巢而出、老将被偷"。只有当我方将军堆 ≥ 敌方最强队伍总军力 90% 时才允许倾巢 all-in。

### 3.2 链式移动与虚拟结算

同一 tick 内的指令按顺序结算且前一条结果对后一条可见，因此一个兵团一 tick 可以走 4 步。`emitChain` 在发出每条移动前做与引擎一致的虚拟结算：`half:false` 时 `k = n−1`（沿途留下 1 兵驻守、吸收己方格驻军），进入敌格要求 `k > 守军`，占格后更新信念地图。踏入未知格后若兵团 <60 兵则截断本 tick 链（防撞上山地/城市导致后续指令从错误格子出发）。

### 3.3 防御子流程

- **反杀**：威胁格与将军相邻且比我守军弱 → 将军直接吃掉它；
- **拦截**：威胁在 8 格内且我方最大野战兵团吃得下 → 全速前出半路截杀；
- **收拢**：否则 30 格半径内所有兵团向将军收拢（最大的全速，其余各走一步）。
- `alert` 计数器提供 6 tick 的警戒滞回，防止威胁在阈值附近反复横跳。

威胁判定：将军 16 格 BFS 半径内，敌方 ≥6 兵的堆按 `兵力/(1+0.4×距离)` 加权；超过 `0.7×守军+2`，或近距离大堆、或 ≥14 兵逼近 5 格内即触发。

### 3.4 剩余编制

按兵力降序遍历其余兵团（将军大堆留守不动）：

1. 邻格捡漏：可占的中立空地（或 ≥55 兵时踏入未知格强行开城）；
2. 邻格骚扰：吃 `兵力+3` 以内的弱敌边角，且不招惹总军力 > 我方 0.9 倍的队伍；
3. ≥8 兵的兵团参与磨地（每 tick 最多 2~3 次 Dijkstra，大图限 2）；
4. ≥45 兵且离家长远的闲散兵团收拢回家。

## 4. 确定性与复现

- 不用 `Math.random / Date / performance / crypto`；唯一随机源是 `seed+id` 哈希驱动的 mulberry32（当前主要用于极少量的次序扰动，路径分歧由每格固定的 `tileJitter` 扰动承担，它只依赖格子编号，天然可复现）。
- 所有控制流只依赖观察输入与自身记忆：同一地图种子、同一名单、同一对手脚本 ⇒ 决策序列逐 bit 相同。
- 播放速度只影响展示节奏，不进入任何决策路径。

## 5. 复杂度与资源

- 每 tick：知识/信念/危险图/腹地/收集 O(N)；`computeThreat` 与 `homeDist` 两次 BFS O(N)；Dijkstra 至多 ~6 次（进攻 ×2、磨地 ×1+2~3、防御时 1 次），每次 O(N log N) 但带探索上限（进攻 320 / 磨地 200 / 拦截 30）。
- 全部大缓冲区（距离场、前驱、堆、信念）跨 tick 复用，单次 decide 的堆分配只有少量小对象，GC 压力极小。
- N 最大约 2.8 万格（16 人辽阔图）。本地自测中 64×62 八人图 p50≈0.3ms、p95≈16ms，远离 200ms 限制；文件约 30KB，远小于 100KB 上限；输出恒为 ≤4 条移动 + `memory:null`，远小于 32768 字符。
- 兜底：`decide` 整体 try/catch，任何异常返回空 moves；输出前做结构校验（坐标整界内、方向合法、≤4 条），杜绝"格式非法出局"。

## 6. 已知局限与设计取舍

- **防守以将军为唯一核心**：不主动守城市与分散领土，敌方大部队碾边角时靠"吞地换地"而非逐格防守。
- **组队协作有限**：队友格只当作可通行/可增援的地形，不主动支援队友将军，也不做集火协同。
- **迷雾估计有系统性偏差**：视野外敌军按增长率线性外推，对方若把兵力囤在未见处，斩首可行性判断会偏乐观/悲观；用代价放大（×1.4~×1.7）、陈旧情报冗余（×1.5+4）和危险图绕行部分对冲。
- **不做对手建模**：不预测对方意图、不追踪敌方指令历史；博弈深度是单层贪心 + 目标黏滞。
- **中立城驻军假设 40~55**：未目击驻军的中立城按 45 估计，与协议范围一致但个别对局可能偏差。
- **边缘一圈视为山地**：协议保证，寻路直接封边。
- **吞地战争消耗**：与敌方大兵团对碾时每格成本 ~2 兵，若生产速度落后会陷入消耗劣势；此时依赖斩首/夺城目标扭转。
- **半军出征的保守性**：守家底线在敌军总量巨大时会压低出征频率，极端情况下偏龟缩，靠末期"落后搏命"阈值（−25）破局。
