# 将军棋策略 (junqi-2)

## 概述

一个完全确定性、同步、零依赖的将军棋 AI 策略，运行于独立 Web Worker。
核心思路：**快速扩张占地产兵 -> 重点攻占中立城市 -> 猎杀敌方将军 -> 防守己方将军**。
每 tick 在本地模拟战局后，按优先级分配最多 4 条指令。

## 算法结构

每次 `decide(o)` 按以下流水线执行：

1. **状态合并**：把观察到的地形写入持久记忆；刷新己方将军、玩家队伍、已知敌方将军。
2. **本地模拟**：克隆 `owner` / `army`，后续选指令都在克隆上逐步更新，保证同 tick 内指令不冲突。
3. **防守**：处理与己方将军相邻的敌方威胁。
4. **猎杀将军**：若已知敌方将军相邻且能打赢，立即全力攻占。
5. **攻城**：攻占可打下的中立城市（或先汇聚兵力再打）。
6. **攻击高价值目标**：敌方城市、靠近敌方将军的格子。
7. **链式扩张**：用剩余指令做多格连续扩张（leapfrog）。

## 状态记忆

- 长期状态保存在模块顶层变量 `G` 中（协议允许顶层变量跨决策保留，每局 Worker 独立初始化）。
- `terrain` 一旦侦察过就永久记住；`owner` / `army` 只信任当前可见部分。
- 每 tick 从观察中重新提取己方领土与军队，保证与真实状态一致。
- 见过一次的敌方将军位置会被记录，直到再次可见确认其已不再是将军。
- 不使用 `Date`、`Math.random`、`performance` 等非确定性输入，同一输入序列完全可复现。

## 战术细节

### 扩张

- 对每个可出发的己方格子，评估四个方向：
  - 目标必须是空地/城市/敌方格，不能是山地。
  - 中立空地得分 = 基础分 + 未知邻居数 x25（开图奖励）+ 可通行邻居数 x3 + 目标偏置。
- 移动方式默认 `half: true`（搬一半），既占领新格又保留后方兵力。
- **链式移动**：同一 tick 内，刚占领的格子如果兵力 >= 2 可以继续出发，实现一 tick 推进多格。

### 目标偏置（BFS 距离场）

- 每 tick 以所有已知中立/敌方城市和敌方将军为源做多源 BFS（未知地形按可通行处理）。
- 生成到最近目标的距离场，距离越近的格子获得越高扩张加分，把扩张方向引向有价值目标。

### 攻城

- 中立城市驻军 40~50。只有满足 `k > 驻军` 才进攻，避免白送军队。
- 若相邻格兵力 >= 驻军 + 2，用 `half: false`（全兵减一）一击攻占。
- 若单格兵力不足，但周围己方格可调集的兵力足够，则先用 `half: false` 把周围兵力汇聚到攻城格，再在同 tick 内攻占。

### 猎杀将军

- 敌方将军一旦进入视野即永久记录位置。
- 当它与己方格子相邻且能打赢时，优先于其他所有行动发起攻击。
- 击杀后接收其全部领土，将军格变为城市。

### 防守

- 扫描与己方将军四邻接的敌方格子。
- 若能反打（相邻己方格 `n-1 > 敌兵力`），先反打消除威胁。
- 若不能反打且敌方 `兵力-1 > 将军兵力`，则把相邻己方军队以 `half: false` 回填将军格，使其无法被一击攻陷。

## 复杂度

- 每 tick 时间复杂度 `O(W x H)`：多次全图扫描 + 一次多源 BFS + 链式扩张的局部搜索。
- 最大地图约 168 x 164（约 2.7 万格），全部计算量远小于 200ms 预算。
- 空间复杂度 `O(W x H)`，全部存于顶层变量，不依赖返回的 `memory`。

## 局限与设计取舍

- **贪心策略**：每 tick 只做局部最优选择，没有跨多 tick 的全局战役规划。
- **攻城时机**：只有"可直接攻占"或"当 tick 可汇聚足够兵力"时才投入指令；否则继续扩张，等待兵力自然增长。
- **信息可能过期**：敌方将军被第三方击杀后，在再次看见前仍会被当作目标，可能造成少量无效行军。
- **团队模式**：仅做到不攻击队友、不把队友城市当目标；不主动协防队友将军。
- **不建模对手**：不预测其他玩家的指令与心理，纯粹基于可见状态做反应式决策。
- **memory 字段**：未使用（返回 `null`），因为协议允许顶层变量持久化，且全图状态超出序列化预算。
