# 将军棋策略（junqi-2）—— “稳扎稳打”

单文件 `strategy.js`，顶层定义 `decide(observation)`，无任何外部依赖、无网络/存储/随机源，
同步计算，任何异常都降级为合法的空指令返回。

## 一、总体架构

每 tick 从当前观测**全量重规划**，不保存任何“计划中的路径”。跨 tick 只持久化**情报**。
这样做的收益：

- 抗干扰：上一 tick 的路径不会被敌方在本 tick 的行动打乱后继续误用；
- 可复现：决策只依赖当前观测 + 累积情报，无隐藏控制流；
- 简单可查：每个 tick 是一次独立的模式决策。

模式优先级（每 tick 按序判定，取第一个成立的执行）：

1. **斩首**：已知敌将位置，且推演兵力足够 → 主力全速行军（4 条指令全用于行军）。
2. **保家**：可见敌军大兵闭逼近我方将军 → 邻接格回填 + 附近兵力沿父链回送将军。
3. **夺城**：主力足够吃下最近的中立城/敌城 → 行军夺城（城市等于“每 tick 产的第二个将军”）。
4. **扩张 + 收拢**：向最近的可占领格链式推进；剩余指令把领地内富余兵力送回将军。

## 二、移动执行模型（效率核心）

利用“同一 tick 内 4 条指令按序结算、前一条结果对后续可见”的规则：

- 所有推进都用 `half: false`（移动 n−1）：**沿途每格只留 1 军**，即可占住该格
  （中立空地守军为 0，k=1 即可攻占），主力只按“每 hop 1 军”的速率消耗；
- **链式推进**：一条 BFS 路径在同一 tick 内连走最多 4 步，行军速度 = 4 格/tick；
- **顺路吸收**：路径经过的己方格兵力并入主力（推演公式：己方格 `−1 + a`，
  攻占格 `−1 − d`），因此行军出发后越走越强；
- `half: true` 只用在一种场景：**从将军格出兵时留一半驻军**（兵力 ≥30 时启用），
  防止主力离开后被斩首。
- 扩张对迷雾格用“乐观估值”（守军视为 0）：1 军也敢去踩未知地，单步损失上限 1 军，
  换取更快铺地与侦察。

## 三、各模式细节

### 斩首（最高优先级）
- **情报来源**：任何 tick 里 `terrain=3` 且可见属主为敌人的格，记录
  `{位置, tick, 当时兵力}`；引擎保证被看过的将军位置在 terrain 中永久标记，
  我方负责记住“是谁的、看它时有多少兵”。
- **守军估计**：可见取精确值；否则 `目击兵力 + 经过tick × 产量g × 2`，
  并以**对方公开的总军力**（players 数组）封顶——将军兵力不可能超过总军力，
  对方总军力骤降（刚打完仗）时机会自动浮现。
- **出兵条件**：`推演到达兵力 > 估计守军 + 余量(12)` 且 `≥12`。
  到达兵力由全路径推演得出（含沿途吸收、每 hop 留 1、迷雾格估值）。
- **止损**：行军途中每 tick 重新推演；临门时目标格进入视野，`runPath`
  会用**精确守军**做最后一跳校验，打不动就不发指令，主力不会白白撞死。
  已逼近（≤10 格）仍不够时进入 50 tick 冷却；对方总军力跌到主力 0.8 倍以下时解除。
- **与保家的冲突**：将军告急时一般放弃斩首转入防守；例外是我方将军守得住，
  或本 tick（≤4 hop）就能得手且威胁还远（≥5 格）。

### 保家
- 每 tick 扫描所有**当前可见**的敌格（守军 ≥8），估计其到我方将军的有效距离
  （相邻己方格的 BFS 距离 +1，无则以切比雪夫距离近似），≤8 格内取最大者。
- 触发条件：3 格内敌军 > 将军守军 +2；或 8 格内敌军 ≥12 且
  > 将军守军 + 一半的近距离可回援兵力。
- 应对：邻接格按军力降序回填将军（n−1 全额转移），再从 10 格内的大格沿
  “到将军的父链”链式回送。

### 夺城
- 候选：所有已知非己方、非队友的城市格。可见中立城/敌城取精确守军，
  迷雾城估 48（规则为 40~50）。敌城要求更高余量（+14 vs +8）。
- 按 `切比雪夫距离 + 守军/8` 排序取前 5 逐一推演，第一个
  `到达兵力 > 守军 + 余量` 的执行。行军途中每 tick 复查，临门精确校验。

### 扩张
- 源格选择：己方 `兵力 ≥2` 的格中取 `兵力 + 前线加成3` 最大者
  （前线 = 邻接可占领的空地/未知地）；主力（≥40）尽量留作行军种子。
- 目标：从源格做限制性 BFS（绕开山地/城市/敌将格/可见敌格/队友格），
  取访问序中第一个可占格——即“最近的可占格”。
- 一 tick 最多 4 轮“选源→寻路→推进”，用满指令预算；走完一条路径后
  新头部可继续被选源，形成连续蛇形推进（1 军/tick 的早期扩张节奏由将军产量决定，
  这已是规则下限）。

### 收拢
- 开启条件：`tick ≥80` 或 `领土 ≥30`（早期产能全部优先投入扩张）。
- 领地内（到将军 BFS 距离 ≥2）`兵力 ≥4` 的最大格沿父链向将军输送，
  传送带式链式推进——用于回收每 25 tick 一次的土地产出，并把将军堆成
  防守底仓与下一次行军的出兵池。

## 四、状态记忆

- **顶层变量 `S`**（每局 Worker 独立初始化一次，跨决策保留）：全部工作缓冲
  （Int8/Int32 Typed Array：地形/属主/驻军扁平副本、BFS 距离/父指针/队列、
  各种标记位）+ 情报表。
- **memory（双保险）**：只序列化 `gens`（敌将目击）与 `killCd`（斩首冷却）两份小表；
  正常情况下顶层 `S` 一直在，memory 恢复只是防御性兜底。
- **不持久化路径/计划**：每 tick 重算，理由见“总体架构”。
- 引擎本身已替我们记住“已侦察地形”（含被见过的将军位置标记），
  因此 memory 无需存地形。

## 五、迷雾与信息利用

- 严格区分 `owner = -2`（视野外，属主未知）与 `-1`（可见的中立）：
  迷雾空地按 1 军估值（扩张时乐观按 0），迷雾城市估 48，迷雾敌将估 40（另有专门公式）；
- 视野 = 己方格 8 邻域，行军主力本身就是一个移动侦察点，接近目标时自然获得精确情报；
- `players` 公开的各玩家**总军力/领土**是重要信号：用于给敌将守军封顶、
  发现“刚打完仗变弱”的斩首窗口、残局判断领先/落后调整激进程度。

## 六、复杂度与性能

- 地图上限 16 人辽阔场 `168×164 = 27552` 格。每 tick：
  - 全图扫描常数次（扁平化、威胁、主力、敌将目击）：~6 次 O(WH)；
  - BFS ≤7 次（己方领地 1 + 行军 2 + 扩张 ≤4），每次 O(WH)；
  - 其余为 O(候选数 × 路径长) 的推演。
- 总计约 `10 × WH` 量级的简单整型操作（~30 万），配合 Typed Array 与复用队列，
  典型耗时在个位数毫秒，对 200ms 限制有 >20 倍裕度；初始化仅为数组分配，远低于 1500ms。
- 返回值 ≤4 条移动 + 两张小表，JSON 远小于 32768 字符；所有数字均为有限整数。

## 七、确定性与可复现

- 不使用 `Date / performance / Math.random / crypto`；
- 所有并列用“行优先扫描顺序 / BFS 访问顺序”打破，结果只由
  （地图种子 → 观测序列 + 累积情报）决定，同种子同名单可重赛复现。

## 八、参数速查

| 参数 | 值 | 含义 |
| --- | --- | --- |
| 敌将衰退系数 | g×2/tick | 估计敌将自目击后的兵力增长 |
| 斩首余量 | 12（领先 25 / 落后 5） | 到达兵力需超过估计守军的量 |
| 斩首冷却 | 50 tick | 逼近仍打不动时的重试间隔 |
| 夺城余量 | +8（敌城 +14） | 夺城需要的富余兵力 |
| 将军出兵留半阈值 | 兵力 ≥30（扩张 ≥12） | half:true 保留驻军 |
| 收拢开启 | tick ≥80 或领土 ≥30 | 早期全力扩张 |
| 威胁半径 | 8 格 / 触发守军 ≥8 | 保家模式的灵敏度 |
| 残局窗口 | 距 maxTicks 250 tick | 依军力对比调整激进程度 |

## 九、局限与设计取舍

- **无对手建模**：不预测具体对手的个性策略，只用可见兵力与公开总量做静态估计；
  敌将“龟缩流”会把主力堆过我的估计上限，最坏情况是长途行军后在临门校验处止损折返（主力不损失，但浪费行军时间）。
- **单线程任务**：每 tick 只执行一个行军任务（斩首或夺城），不做多路佯攻；
  换取实现简单与每 tick 决策的可解释性。
- **防守只覆盖将军**：城市/边疆被骚扰不触发专门防守，靠扩张夺回与将军囤兵威慑；
  被蚕食边疆时土地分会缓慢流失。
- **无专项侦察调度**：不派专职探子，靠扩张蛇与行军主力的自然视野发现敌将；
  大地图多人生局中找到第一个敌将可能较晚。
- **组队模式无配合**：仅保证不误伤队友（不把兵力赠入队友格、不打队友城），
  没有联合作战逻辑。
- **迷雾穿透风险**：行军路径上的迷雾格可能是敌军大兵营（估 1 军），
  会损失先头兵力后自动重规划；扩张侧同理（乐观估 0），单次损失上限很小。
- **参数为人工推理值**：上表阈值基于规则推演设定，未经过实测对局调优
  （本文不含任何虚构的实测战绩/胜率数据）。
- **超时判胜策略简单**：残局仅调整激进程度，不做“最后 N tick 精确控分”之类的操作。
