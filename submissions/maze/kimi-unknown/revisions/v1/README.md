# 迷宫竞速策略说明

## 总体设计

两份策略都只使用 `observation` 中公开、确定的信息，不使用网络、DOM、随机数、时钟或外部文件。地图种子、尺寸和规则相同即可复现决策。

核心取舍是优先保证逃生，其次尽量保持速度与生命，再考虑晶片和探索分。逃生成功有 6000 分，远高于任何单项附加分，因此不会为了晶片进行无限制绕路。

---

## `strategy.js`：走迷宫策略

### 1. 地图预处理与缓存

首次看到某个种子和尺寸时，策略会建立以下确定性数据：

- 可通过格子的布尔数组；
- 闸门、机关所在格的索引；
- 从钥匙出发的静态 BFS 距离；
- 从出口出发的静态 BFS 距离；
- 从每个初始晶片到钥匙、出口的静态 BFS 距离。

静态 BFS 把闸门视为可通过，只排除固定墙。原因是闸门会周期开放，静态距离适合作为最短路径下界和 A* 启发函数；真正搜索时再按出发 tick 检查闸门是否关闭。

缓存以 `seed + width + height` 为键，保存在顶层变量中。它只缓存地图派生数据，不保存不可序列化对象，也不参与随机决策。

### 2. 目标选择

基本目标为：

1. 没有钥匙时前往钥匙；
2. 拿到钥匙后前往出口。

晶片采用有界顺路策略。对每个尚未收集的晶片计算：


detour = dist(当前, 晶片) + dist(晶片, 主目标) - dist(当前, 主目标)
只有 detour 为正且不超过预算时才临时把该晶片作为目标：
拿钥匙前预算约为 25；
拿钥匙后预算约为 15；
接近 maxTicks 时逐步收紧预算。
该预算同时考虑晶片分值、延迟逃生造成的速度损失和绕行带来的少量探索收益。晶片若离追逐者太近，还会额外增加代价，避免为低收益晶片主动进入危险区域。
3. 时间感知 A*
每次决策都重新从当前位置搜索，而不是机械执行旧路径。搜索状态包含：
当前格；
从本 tick 起已经过的 tick 数；
追逐风险值；
父状态和到达该状态的动作。
每次转移使用决策发生的绝对 tick t 检查：
目标格是否为固定墙；
若移动进闸门，该 tick 闸门是否关闭；
若移动到机关格，该 tick 机关是否激活；
玩家在该 tick 是否仍处于无敌期。
这符合结算规则中的同时决策和按当前 tick 结算。等待也作为一个转移；玩家站在已关闭闸门上时，等待和向外移动不会被错误禁止。
每个格子最多保留少量非支配到达记录，比较维度包括：
更早到达；
追逐者到达余量更小，即更安全。
A* 的优先值包含：
Text
实际经过 tick + 到目标的静态 BFS 启发距离 + 追逐风险罚分
风险罚分只作为软偏好；风险格是否被硬禁止由下面的分级机制决定。
4. 追逐风险模型
由于无法知道本轮实际抽中的第三方 hunter.js，runner 不假设追逐者只会贪心。它为每个追逐者计算一张“忽略闸门关闭”的 BFS 距离图。忽略闸门是保守上界：追逐者可能无法立刻穿过关闭闸门，但未来一定可能到达。
对计划在未来 tick s 到达的格子，计算从当前到 s-1 之间追逐者拥有的行动次数，并比较：
Text
追逐者最短距离 <= 可用行动次数
若成立，说明该追逐者理论上能够到达该格，于是将该格视为危险。
当前 tick 另做更精确的检查：
若追逐者本 tick 不行动，禁止进入其当前格；
若追逐者本 tick 行动，禁止进入任一追逐者当前格及其所有合法相邻移动格；
玩家处于无敌期时暂时忽略碰撞风险。
搜索按以下顺序逐步放松：
禁止所有理论上可达的追逐危险格；
要求追逐者至少提前 1 次行动才视为危险；
要求至少提前 2 次行动；
只避免当前 tick 的立即碰撞；
暂时忽略未来追逐风险。
前四级都找不到路时，才使用第五级。若玩家生命大于 1，第五级允许一次受控碰撞：利用碰撞后的 3 tick 无敌窗口穿过封锁。这是有意的设计，因为完全拒绝碰撞可能在死路里无限僵持；但策略不会主动用最后 1 点生命做这种交换。
若所有搜索都失败，最后使用局部回退：
排除墙、当前关闭闸门和会立即造成伤害的机关；
优先选择离目标更近的格；
避开当前可被追逐者进入的格；
在无法完全避开时仍选择一个合法动作，而不是输出非法值或陷入异常。
5. 状态记忆
每次返回的 memory 是小型 JSON 对象，包含：
seed；
当前 tick；
本次动作；
当前目标；
目标是否为顺路晶片；
地图初始晶片数。
大量派生状态放在顶层地图缓存中，因此 memory 保持很小。即使缓存丢失，代码也可以从当前完整 observation 重建地图。
6. 复杂度
令：
N = width × height，最大为 35 × 25 = 875；
H 为追逐者数量，最大为 3；
C 为晶片数量，最大为 16；
P 为 A* 展开状态数，单格最多保存 4 条记录并有额外展开上限。
预处理复杂度：
Text
O((C + 2) × N)
每次 runner 决策：
追逐者 BFS：O(H × N)；
当前位置 BFS：O(N)；
必要时一个目标距离 BFS：O(N)；
A*：上界约为 O(P log P)，每个状态最多扩展 5 个动作；
实际 P 受每格记录数和展开上限约束。
空间复杂度：
Text
O((C + 2) × N + P)
hunter.js：追逐策略
1. 距离场
每次行动时建立：
从玩家当前位置出发的 BFS；
从玩家当前目标出发的 BFS，目标在拿钥匙前是钥匙，拿钥匙后是出口；
每个追逐者到全图的 BFS；
所有追逐者到每格的最小距离。
追逐者移动只受固定墙和当前关闭闸门限制，不受机关伤害影响，也不会收集道具。
2. 玩家下一步预测
玩家可能等待、向目标靠近或避开追逐者。策略先列出玩家的合法下一步，并按以下因素排序：
到钥匙或出口的静态距离；
到最近追逐者的距离，通常越远越安全；
当前机关是否激活；
是否只能等待。
最多保留三个最可能的下一格。
同时构造一条预测路线：
从玩家位置出发；
每一步优先选择到目标距离减一的格子；
并列时偏向离追逐者更远的格子；
会少量考虑未来闸门和机关状态。
由于玩家和追逐者同时决策，追逐者不会只盯玩家当前格，而会重点考虑下一次追逐行动时玩家可能已经前进的 hunterEvery 步。
3. 多追逐者拦截
对每个追逐者的每个合法动作，重新从目标格做一次 BFS，并计算：
到玩家最可能下一格集合的最短距离；
到预测路线未来点的最短距离；
到玩家当前格的图距离；
到钥匙或出口的图距离；
与玩家当前位置的几何距离；
是否位于激活机关上；
是否已有其他追逐者选择同一格；
是否只是返回上一位置。
综合评分会：
优先覆盖玩家可能的下一步；
提前移动到玩家路线前方；
在玩家拿钥匙后更重视出口封堵；
让多个追逐者略微分散，而不是无条件全部重叠；
保持完全确定的动作次序。
这不是对每个玩家策略的严格逆向，而是一个低成本、适应性较强的预测模型。
4. 状态记忆
memory 保存每个追逐者上一决策时的位置和动作，用于轻微惩罚立即回退，减少在狭窄通道中的无意义来回。
地图缓存仍由顶层变量保存；memory 本身很小。
5. 复杂度
每次 hunter 决策最多执行：
玩家距离 BFS：1 次；
目标距离 BFS：1 次；
追逐者距离 BFS：H 次；
每个追逐者最多 5 个候选动作，每个候选 1 次 BFS：5H 次。
因此时间复杂度为：
Text
O((5H + 2) × N)
空间复杂度为：
Text
O(N)
实际最大规模约为 18 × 875 次 BFS 格子访问，不含大常量路径状态。
设计取舍
优先逃生
策略把最高优先级放在找到一条可执行的钥匙—出口路径，而不是最大化局部晶片。受控碰撞只在保守搜索全部失败且生命大于 1 时启用。
可复现性
所有排序和并列处理都是确定性的。没有 Date、performance、Math.random、crypto、网络或其他外部输入。
快速重规划
每 tick 重新规划，而不是长期依赖旧路线。这样能响应：
追逐者移动；
玩家无敌期变化；
闸门相位变化；
机关相位变化；
晶片被收集；
拿到钥匙后的目标变化。
代价是每 tick 都有一定计算量，但最大地图只有 875 格，且 A* 有每格记录数和展开数上限。
局限
追逐者意图不可知
runner 无法知道本轮实际抽中的 hunter.js。使用“理论可达”作为硬风险会产生保守路径，可能放弃实际上安全的路线。
追逐距离是保守上界
追逐者 BFS 忽略未来闸门关闭，因此可能高估追逐者到达速度。这样能减少漏判，却会增加误判。
周期性时间状态被有限记录
A* 每格只保留少量非支配状态并有展开上限。复杂的多闸门等待路线理论上可能不是全局最优，但保留了有限的多时刻选择，并有逐步放松与局部回退兜底。
受控碰撞不是无损策略
它用于打破死路封锁，并依赖碰撞后的无敌窗口。面对非常强的围堵，仍可能连续损失生命。
晶片收集是贪心顺路，不是全局面最优
没有维护晶片子集状态，也没有求解带晶片收集的旅行商问题。这样避免了指数级状态空间，但会错过某些高分晶片组合。
hunter 的玩家预测是启发式
它假定玩家大体朝钥匙或出口前进，同时会回避追逐者和机关。对刻意绕路、假动作或专门反制该模型的玩家，拦截精度会下降。
没有理论必胜保证
地图含环路、多个追逐者和周期机关；完整对抗搜索代价过高。本方案选择的是在 200ms 决策限制内可稳定执行的概率性与防御性策略。
