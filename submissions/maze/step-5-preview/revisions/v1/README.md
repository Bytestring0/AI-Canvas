# Maze Race Strategies

本仓库包含两份独立策略：`strategy.js` 为走迷宫方，`hunter.js` 为追逐方。两份文件都不使用网络、DOM、第三方库、随机数或时钟，只依赖单次 `decide(observation)` 传入的完整观察。

---

## 1. `strategy.js`：走迷宫策略

### 1.1 静态地图缓存

首次决策时，策略会根据 `seed`、地图尺寸和 `grid` 内容建立缓存：

- `passable[y][x]`：只看固定墙，`0` 视为可通行。
- `gateAt` / `trapAt`：把周期性闸门、机关按坐标索引，便于快速判断。
- `distCache`：以某个目标为源点的 BFS 最短路数组，按需计算并缓存。

由于题目保证“忽略周期闸门时所有通道互通”，静态 BFS 可以保证在非周期图上找到目标。

### 1.2 全局路线选择：Bitmask DP

走迷宫方需要先拿钥匙，再到达出口；晶片是可选加分。策略在首次决策时，对以下点集做一次静态路径规划：

- 起点
- 所有尚未收集的晶片
- 如果还没有钥匙，加入钥匙点
- 出口作为最终点

设点数为 `P`，其中 `P <= 17`（最多 16 晶片 + 1 钥匙）。用一个 bitmask DP 计算：

state = (已访问点集合 mask, 当前最后一点 last)
dp[state] = 从起点走到该状态的最短静态步数
转移时尝试走到任意尚未访问的点。最终状态必须包含钥匙，然后走到出口。目标函数不是单纯最短步数，而是近似分数：

text

score = 2000 * finish / maxTicks
        - 1000 * collectedCoins / totalCoins
        + 800 * max(0, finish - 0.65 * maxTicks) / maxTicks
这样会在“更快逃生”和“多拿晶片”之间做权衡。最后一项是对接近超时的路线施加软惩罚，避免为了晶片把静态完成时间推到很接近 maxTicks。

如果 DP 不可行或点数超过 20，退化为基础路线：必要时先去钥匙，再去出口。

1.3 每 tick 移动：时间展开 A*
每 tick 根据当前路线找到下一个未完成目标，然后运行一个带时间维度的 A* / Dijkstra：

状态：(x, y, tick offset)。
边：up/right/down/left/wait。
进入格子前检查固定墙。
进入闸门前检查当前 tick 是否关闭。
进入当前 tick 已激活的机关会被重罚，除非绕行代价更高。
等待闭门、等待机关周期过去都是允许的。
启发函数使用静态 BFS 到目标点的距离。
追逐者威胁通过多源 BFS 得到“到最近追逐者的静态距离”，并作为代价惩罚；在追逐者行动 tick 特别惩罚相邻格。
时间视野 H 不是固定拉满，而是根据静态距离动态设置：

text

H = clamp(max(staticDist + 80, staticDist * 2 + 40), 1, min(600, maxTicks - tick))
如果 A* 因视野或代价问题失败，会退化为局部合法动作评分，选择更接近目标且更安全的动作。

1.4 安全覆盖层
A* 返回第一步后，还会做一次合法性/安全性检查。如果首选动作会：

进入当前激活机关；
与追逐者同格；
在追逐者行动 tick 进入追逐者相邻格；
则重新在所有合法动作中评分选择。合法动作评分同样考虑静态目标距离、机关、追逐者威胁、是否继续上次动作。

1.5 状态记忆
memory 只保存上一个动作：{ last: action }。
路线、静态距离、A* 缓冲区等保存在 Worker 顶层变量中，不进入 JSON memory。
不使用 Date、performance、Math.random、crypto。
相同地图、相同观察序列会得到相同决策。
2. hunter.js：追逐策略
追逐方只在 (tick + 1) % hunterEvery === 0 时被调用。此时玩家和追逐者同时决策，追逐方看不到玩家本 tick 的最终动作。

2.1 一步同步博弈评估
策略不假设玩家会继续沿当前路线走，而是枚举玩家在当前 tick 的所有合法终点：

原地等待；
四个方向中不撞墙、不进入当前关闭闸门的格子。
然后枚举每个追逐者的所有合法动作，包括等待。由于追逐者最多 3 个，每个追逐者最多 5 个动作，组合数不超过 5^3 = 125。

对每个组合，预先用 BFS 计算从每个“玩家可能终点”到全图的最短距离。评估指标按优先级如下：

是否能覆盖所有玩家可能终点：如果能，则该组合可以保证无论玩家怎么走都被抓到。
最小化最坏情况下玩家到最近追逐者的距离。
最小化所有玩家可能终点的距离和。
最小化追逐者到玩家当前格的距离，保持压迫。
最终为每个追逐者输出恰好一个动作。

2.2 闸门与规则
追逐者与玩家一样受固定墙和当前 tick 关闭闸门阻挡；站在关闭闸门上仍可向外移动。追逐者不受机关伤害，不收集道具，可以互相重叠。

2.3 状态记忆
hunter.js 不使用 JSON memory，每次返回 memory: null。静态地图缓存保存在 Worker 顶层变量中。

3. 复杂度
3.1 走迷宫方
设地图通道格子数为 N = width * height，最多 N = 875。

静态 BFS：O(N)。
Bitmask DP：点数 P <= 17，状态数 O(2^P * P)，转移数 O(2^P * P^2)。
每 tick A*：时间视野 H <= 600，最坏状态数 O(H * N)，堆操作 O(log(H * N))；实际通常小于该上界。
每 tick 追逐者威胁 BFS：O(N)。
JSON memory：仅一个字符串，体积极小。
3.2 追逐方
BFS 次数：玩家可能终点最多 5 个，加当前玩家位置 1 个，共 O(6N)。
动作组合数：O(5^K)，其中追逐者数量 K <= 3。
组合评估：O(5^K * K * D)，D <= 5。
4. 局限与设计取舍
4.1 走迷宫方
全局路线使用静态 BFS，不考虑闸门周期、机关周期和未来追逐者位置；这些由每 tick 的时间展开 A* 局部修正。
追逐者模型是“威胁场”，不是对其他策略的精确预测。它不知道对方是否会包抄、封锁或故意等待。
机关避开是带惩罚的，不是绝对禁止。如果绕行代价极高，策略可能选择踩一次激活机关以保住逃生或速度。
Bitmask DP 在 P <= 20 时使用；题目参数下 P <= 17。若未来规则增加过多晶片，会退化为直接逃生路线。
分数公式中的向下取整没有精确建模；路线选择用的是连续近似分数。
不保证对强追逐策略必胜。
4.2 追逐方
预测玩家只做一步同步枚举，不建立长期拦截路线。
BFS 距离忽略周期闸门当前开关，因此评估的“距离”可能比实际可达距离短。
多追逐者协同是组合优化，不做长期角色分配。
不保证抓住最优走迷宫策略。
5. 可复现性
两份策略都满足：

无时钟、无随机数、无网络、无存储。
所有枚举顺序固定。
相同种子、相同地图、相同观察序列会产生相同动作。
播放速度只影响展示，不影响决策。
