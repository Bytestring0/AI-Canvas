# 迷宫竞速策略说明

## 概述
本项目包含两份策略代码：`strategy.js` 控制玩家完成迷宫通关，`hunter.js` 控制追逐者拦截玩家。两份策略均基于时间敏感的广度优先搜索（BFS）实现路径规划，结合动态目标优先级、状态缓存和风险规避机制设计，严格保证确定性、可复现性和运行效率。

## 一、走迷宫策略（strategy.js）

### 算法原理
1. **目标优先级**：严格遵循「拾取钥匙 → 抵达出口」的核心通关逻辑，在此基础上顺路收集晶片，在保证通关速度的前提下最大化总分。
2. **时间维度BFS**：
   - 扩展传统BFS为「位置+步数」的二维状态，每一步对应实际tick时间，自动计算对应时刻的闸门开闭与陷阱激活状态。
   - 支持原地等待（wait）操作，可用于等待闸门开启或陷阱关闭，避免硬闯造成伤害。
   - 自动过滤墙、关闭的闸门与激活的陷阱，保证路径合法性。
3. **晶片收集优化**：
   - 先计算起点到主目标的最短路径作为基准。
   - 遍历所有晶片，分别计算「起点→晶片→主目标」的总路径长度，若绕路步数不超过5步则选择该路线，兼顾分数与通关效率。
4. **猎人规避机制**：
   - 实时检测所有猎人的曼哈顿距离，当任意猎人距离≤4格时，触发路径重规划。
   - 重规划时将猎人可能到达的区域纳入风险考量，生成规避路线拉开距离。

### 状态记忆设计
通过 `memory` 字段缓存以下信息，避免重复计算：
- `path`：当前规划完成的完整路径数组，每一步包含动作类型与目标坐标。
- `pathIndex`：当前已执行的路径索引，下次调用直接从该位置继续。
- `targetKey`：当前主目标的坐标标识，用于检测目标变更（如拾取钥匙后自动切换为出口）。

仅当目标变更、路径走完、下一步非法或猎人靠近时才触发重规划，绝大多数tick仅需O(1)时间执行。

### 时间复杂度
- 单次BFS最坏复杂度：O(W × H × T)，其中W、H为地图宽高，T为搜索深度（最大为剩余tick数）。
- 实际运行中，闸门与陷阱的周期性使得状态会在周期公倍数后重复，有效状态数远低于理论值。
- 路径缓存机制使得整体平摊复杂度接近O(1)每tick，完全满足200ms时限要求。

### 局限与设计取舍
- **通关优先原则**：核心设计目标是保证成功通关，晶片和探索分数为次要目标，不会为远端晶片大幅绕路。
- **保守风险策略**：默认避开所有激活陷阱与靠近的猎人，极端场景下可能稍绕远路，但最大程度保留生命值。
- **精确最短路径**：使用BFS保证路径最优，相比启发式算法计算量稍大，但针对题目给定的地图尺寸完全适配。
- **短期规避**：猎人规避仅基于当前距离判断，未做长期路径预测，避免过度计算导致超时。

## 二、追逐策略（hunter.js）

### 算法原理
采用「多猎人分工协作」架构，不同ID的猎人承担不同职能，形成包围态势：
1. **追击手（ID 0）**：以玩家当前位置为目标持续追击，保持压力，压缩玩家移动空间。
2. **埋伏手（ID 1）**：提前前往玩家的核心目标点（钥匙或出口）埋伏，截断通关路线，形成「前堵后追」的夹击。
3. **拦截手（ID 2）**：基于玩家历史位置计算移动方向，预测玩家前进路线并前往前方拦截，对直线移动的玩家效率极高。

路径规划同样采用时间敏感BFS，考虑闸门周期性开闭，保证移动合法性。限制搜索深度为10步，平衡计算速度与拦截效果。

### 状态记忆设计
- `lastPlayerX` / `lastPlayerY`：记录上一次决策时的玩家坐标，用于计算玩家移动向量，预测后续位置。
- 各猎人独立计算路径，无需共享状态，逻辑简洁可靠，避免耦合错误。

### 时间复杂度
- 单次决策复杂度：O(N × W × H × K)，其中N为猎人数量，K为固定搜索深度（10步）。
- 由于搜索深度固定，整体复杂度与地图面积线性相关，计算量远低于玩家策略，可轻松满足时限。

### 局限与设计取舍
- **数量依赖**：分工策略在2-3个猎人时效果最佳；单猎人场景下退化为纯追击，拦截能力有限。
- **预测局限性**：方向预测基于上一帧位置，对玩家突然变向、反复绕路的应对能力有限。
- **深度限制**：BFS限制10步深度以保证速度，无法规划超长距离的迂回拦截，适合中近距离作战。

## 三、确定性与可复现性
两份策略均严格遵循确定性设计规范：
- 不使用 `Math.random`、`Date`、`performance` 等任何非确定性输入。
- 所有决策完全基于输入的 `observation` 状态，相同种子、相同tick必然产生完全一致的输出。
- 状态记忆为纯JSON结构，无循环引用、函数或不可序列化值，保证重放与复赛结果完全一致。

## 四、性能优化要点
1. **队列优化**：BFS使用数组+头指针实现队列，避免 `Array.shift()` 的O(n)开销，显著提升搜索速度。
2. **路径缓存**：玩家策略缓存完整路径，绝大多数tick只需索引递增，无需重复搜索。
3. **深度限制**：双方策略均限制BFS搜索深度，避免极端地图下超时。
4. **循环优化**：使用普通for循环替代数组高阶方法，减少函数调用开销，适配沙箱执行环境。
