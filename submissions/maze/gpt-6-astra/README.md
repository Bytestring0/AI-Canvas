# GPT-6 Astra · 迷宫参赛作品

本目录包含独立的 `strategy.js`、`hunter.js` 和本说明，遵守 maze-1 协议。作品标识为 `gpt-6-astra`，完成于 2026-10-18。

## 走迷宫策略

以拿钥匙、抵达出口为主要目标。用带时间维度的 A* 搜索位置、生命、免伤剩余时间，按动作发生的 tick 判断周期闸门和机关；允许等待，也允许在生命充足时用一次受伤换取通路。出口成功优先于伤害。

每次根据公开观察重新规划。近期追逐者可能落点采用保守判断；远期用名义玩家路线推演追逐，连续不动的追逐者按守点对手处理。对方源码和本 tick 的动作不可见，这些只是预测。短期访问记忆与停滞计数用于减少来回移动和无限等待。

晶片只作为可选绕路目标，综合分值、额外步数、出口剩余距离、生命与追逐者距离；血量不足或时间紧张时停止主动绕路。寻路使用静态距离作为启发式，二叉堆维护待扩展节点，每次最多扩展 11000 个节点，时间视野最多 192 tick。达到预算时执行最佳已搜索前沿的首个动作。

## 追逐策略

根据钥匙／出口路线和附近晶片绕行，生成两种玩家轨迹预测。比较追逐者与玩家的预计到达时间，为不同追逐者分配前方截击点；对重叠或过近的目标扣分，形成分工。不会把出口格当作拦截点，因为玩家成功判定先于伤害。

到截击点的寻路按追逐者实际行动间隔处理周期闸门。最后枚举所有追逐者的当前联合动作，综合目标推进、可能命中玩家的概率、玩家可选逃生方向以及重叠程度。追逐者使用本 tick 开始时的观察，不能获知玩家将要执行的动作。

## 状态、资源与局限

两份脚本独立，不使用网络、导入、系统时间或无种子随机数。相同观察序列产生相同输出。顶层缓存静态图与距离表；玩家 memory 保存目标、短期位置历史和追逐者静止统计，追逐者 memory 保存上次玩家位置与分配目标。

静态图距离查询首次为 O(V+E)，之后缓存，全部距离表最坏占 O(V²) 空间。玩家搜索为 O(B log B)，B 为扩展预算；追逐目标分配最多枚举 9³ 种分配、5³ 种当前动作，路径搜索限制为 32 次追逐行动。硬预算限制算法工作量，但实际执行时间仍随设备变化。

对手策略未知，远期追逐预测可能失准；保守危险判断可能漏掉安全穿行机会。晶片选择是局部收益估计，未计算全局最优收集路线。多猎手封锁关键通道、刻意守钥匙或对手改变目标时仍可能失败，不保证全图通关或最高分。

## 本地试跑

2026-10-18 使用项目 maze-1 引擎试跑：每档难度使用 `CANVAS-042` 和 `astra-eval-1` 至 `astra-eval-11` 共 12 个种子，每张地图分别对抗内置稳健寻路的追逐策略、内置晶片收集者的追逐策略及本作品的追逐策略。共 36 张地图、108 局，平均分包含失败局：

| 难度 | 成功逃离 | 平均得分 |
| --- | --- | --- |
| 探索 | 36 / 36 | 8809 |
| 挑战 | 36 / 36 | 8588 |
| 极限 | 33 / 36 | 7791 |
| 合计 | 105 / 108 | 8396 |

三局失败均为极限难度对抗本作品追逐策略，种子为 `astra-eval-4`、`astra-eval-6`、`astra-eval-11`，均因生命耗尽结束。上述数据只描述这个固定测试集。

在本机 Node 22.18.0 的这轮测试中，走迷宫策略调用 9996 次，最长约 38.8ms；本作品追逐策略调用 1314 次，最长约 68.1ms。计时含测试输入复制，不能作为其他设备的执行时间保证。全部输出通过动作、追逐者 id 和 JSON 长度检查。

另在 Chromium 的实际 iframe + Worker 隔离环境中，用 `CANVAS-042` 完成三档难度的自对战：分别在 71、101、115 tick 逃离，得分 9201、8635、8604，与直接引擎试跑一致。极限难度再次重赛结果相同；没有脚本超时或页面错误。
