迷宫竞速 · 策略说明
本目录交付三份文件,遵循 maze-1 协议:

文件	角色	说明
strategy.js	走迷宫(runner)	顶层 function decide(o),每 tick 调用一次,返回 {action}
hunter.js	追逐(hunter)	顶层 function decide(o),在 (tick+1) % hunterEvery === 0 时调用,返回 {actions:[{id, action}]}
README.md	本文档	算法、状态记忆、复杂度、局限与设计取舍
两份 JS 均为纯标准 JavaScript:无 import/export、无第三方依赖、无网络/DOM/存储/额外 Worker;完全同步计算;不使用 Date、performance、Math.random、crypto 等非确定输入;所有返回值只含有限数字与字符串,JSON 序列化体积约几十字节。所有异常均被 try/catch 捕获并兜底返回合法的 wait,因此任何内部错误最多损失走位效率,不会触发 status=error 得 0 分。

1. strategy.js(走迷宫策略)
1.1 每 tick 决策流程
地图静态分析(首个 tick 构建,之后缓存于 Worker 顶层变量):闸门/机关索引与周期查找表、格子度数、环格标记、树深(见 1.6)。
追逐者威胁场:从所有追逐者位置做多源 BFS(只看墙),得到每个格子到最近追逐者的步数 _hDist。
危险判定:最近追逐者约 2 步以内(_hDist × hunterEvery ≤ 6,expert 的 hunterEvery=2 时阈值取 5)→ 进入逃避模式。
时间展开 BFS(核心,见 1.2):先以严格追逐者规避(slack=2)规划;若锚点不可达,依次松弛到 slack=0、完全关闭;完全关闭只在血量 ≥ 2 或剩余时间 < 30 tick 时允许,避免 1 血自杀。
目标选择(见 1.4):锚点(无钥匙 → 钥匙;有钥匙 → 出口)+ 绕行预算内的晶片。
执行:取时间 BFS 父指针链的第一步;若规划失败,退化为静态最短路走一步的兜底。
1.2 时间展开 BFS(闸门与机关的时序建模)
状态是 (格子, tick),而不是单纯的格子。这样可以把周期性障碍物精确地编进搜索:

在 tick τ 结算时移动进入格子 n,要求 n 上的闸门在 τ 开放((τ + phase) % period < on 为关闭,预计算成 period 长度的查找表);
在 tick τ 结束后位于格子 n(无论移动还是原地等待),若 n 的机关在 τ 激活则扣血,所以"τ 时刻激活机关的格子"在该层是禁区——注意伤害比较的是结算后的最终格,所以移动看目的地、等待看当前格,两者用同一个 τ 检查;
站在关闭的闸门上仍然可以向外走(规则允许),因此闸门检查只作用于"进入",不作用于"离开";
每层有 wait 转移,天然支持"等一拍等闸门/机关"的走法。
BFS 按层(即按时间)展开,某格首次到达的层就是最早到达时刻,一次搜索即可同时得到所有格子的最早到达时间与路径父链。为控制单次开销,做了四个剪枝:

前瞻上限 HORIZON = 220 层(并受 maxTicks − tick 截断);
锚点到达后再多搜 26 层即停(晶片绕行预算 ≤ 24,窗口足够覆盖);
等待剪枝:仅当某格至少一个移动方向被闸门/机关时序挡住时才生成"原地等待"状态(等待的意义是解锁时序,最早到达路径不含无用等待);
停滞提前终止:追猎封锁集在 L≈HUNTER_CAP+slack 后不再变化,闸门/机关时序在格子入前沿后 ≤8 层内必然解锁;连续 12 层无新格被发现即截断。锚点不可达时的饱和搜索(220 层全满)由此截断,是单次 decide 耗时的关键保险。
1.3 追逐者规避:威胁场 + 三级松弛
威胁场是静态快照(追逐者本 tick 位置、忽略闸门,偏保守)。追逐者 d 步外的格子,首次被占据的相对时刻约为 d × hunterEvery − 1(它每 hunterEvery tick 走 1 格,首次移动就发生在本 tick 结算;近似值,见第 5 节局限)。规划时把满足

hDist[n] × hunterEvery − 1  ≤  min(相对层数 L, HUNTER_CAP) + slack
的格子视为禁区。其中 HUNTER_CAP = 6 是威胁前瞻封顶(约 2-3 次猎手移动):远期占据位置是 speculation(猎手实际在追人,不会瞬移预判),封顶后远期交给每 tick 重规划适应——不封顶会使封锁半径随路径长度线性膨胀,导致明明可绕的封锁被判死、绕行方案永远规划不出来(实测造成"安全但永远在路上"的僵局)。

slack 的三级含义:

级别	条件	效果
slack = 2	追逐者可能在我到达后 2 tick 内也到	常规规划,主动绕开
slack = 0	追逐者可能与我同时或更早到达	锚点仍不可达时的次级规划
关闭	仅忽略追逐者时序(机关仍严格避开)	最后手段,可能挨打;仅当锚点被封死且 hp ≥ 2 或时间将尽(<30 tick)
这样:平时路径自动绕开危险格;被蹲守/围堵时仍能规划出"强行拿钥匙"的路线(用血换 6000 分的逃生收益);1 血时不会走向必死的位置,转而安全地收集晶片等时机。

危险判定是分层的:1 血用保守半径(更早逃避);血量 ≥2 且安全规划存在时只在贴脸(≤1 步)才打断计划——规划器自身已避免碰撞,频繁打断反而造成"永远在路上";血量 ≥2 且被围/被蹲(无安全规划)时用常规半径逃避。硬闯(挨一次打换无敌帧穿过封锁)仅在突围模式且血量 ≥2,且满足其一:追逐者蹲在锚点附近(蹲守型封锁)、或连续 24 tick 被围困(口袋型封锁)。

出口豁免:持钥时踩出口即成功,"结束优先于伤害和追逐",所以时间 BFS 与逃避模式里,出口格对机关与追逐者检查豁免(闸门仍会物理阻挡进入)——避免出现"守在出口的追逐者吓得我们永远不敢赢"的假死锁。

1.4 目标选择:锚点 + 晶片绕行预算
锚点 = 无钥匙时的钥匙格,或持钥后的出口格。晶片序贯贪心:每 tick 用同一张时间 BFS 的到达表评估

total(coin) = 我→晶片的最早到达层数 + 晶片→锚点的静态步数detour      = total − 我→锚点的最早到达层数
绕行预算由分数结构推导:一枚晶片值 1000 / 总数 分,一个 tick 值 2000 / maxTicks 分(速度分),所以纯经济上的最大绕行是 coinVal / tickVal 个 tick。打 0.65 折作为风险与机会成本折扣(探索分是顺带收益,未计入):

关卡	币值	tick 值	预算(取整,夹在 [6,24])
scout 21×15	125	≈5.56	14
standard 29×21	≈83.3	≈3.57	15
expert 35×25	62.5	2.5	16
另有两个闸门:时间可行性(total + 12 ≤ 剩余 tick,END_MARGIN=12 覆盖闸门等待与轻度逃避),以及绝望规划(offRun,锚点被封死强行突围时)不捡币直奔锚点。为防止两枚代价接近的晶片之间来回摇摆,设置了目标迟滞:沿用上轮目标,除非新目标至少好 4 tick。每 tick 全量重评估,捡完一枚自动转向下一枚或锚点;钥匙到手后锚点切换为出口,出口附近的币自然被"顺路"逻辑覆盖。

1.5 逃避模式
触发即覆盖目标逻辑(清空迟滞)。对 4 个移动与等待各打分:

score = 距最近追逐者步数 × 10      − 树深 × 12            (惩罚深入死胡同,权重略高于距离收益)      + 环路/三岔口 + 2      + 朝锚点方向的第一步 + 4   (边逃边推进)      − 原地等待 3
候选格若当前 tick 关闭闸门、机关激活则直接排除(持钥且下一步是开放出口时立即获胜,优先返回)。玩家 1 格/tick、追逐者 1 格/hunterEvery,速度是 2–3 倍;在环上持续奔跑即可保持甚至拉开距离,这也是"树深惩罚"的依据:被逼进树状分支(死胡同)才是致命的,环与岔口才是安全区。

1.6 静态拓扑:环格与树深
环格判定:删点连通性——对每个通道格 c,封锁 c 后从其一个邻居 BFS,若能不经过 c 绕到另一个邻居,则 c 在某个环上。复杂度 O(N·(N+E)),每局一次。
安全格 = 环格 ∪ 度数 ≥ 3 的格子。
树深 = 到最近安全格的步数(多源 BFS)。逃避模式用它惩罚死胡同深度。
1.7 兜底链
规划失败(理论上不应发生)时依次退化为:时间 BFS 目标不可达 → 就近可达晶片;路径提取失败 → 静态最短路走一步(避当前关闭闸门,机关/追逐者仅降权);再失败 → 对锚点做同样的静态走一步;最后 wait。任何一环都不抛异常。

2. hunter.js(追逐策略)
2.1 目标推断与路径预测
玩家没有钥匙时其理性目的地必然是钥匙(否则上限 2000 分),持钥后是出口。以该格为目标做 BFS,从玩家当前位置沿距离梯度下降重建"玩家的推测最短路",作为预测依据。这是追逐者唯一需要的"建模":不猜玩家代码,只猜其收益结构。

2.2 时序模型
追逐者的决策在 tick t 开始时做出,移动在 t 的结算时执行(玩家先动)。追逐者 d 步外的格子,第 d 次移动发生在相对时刻 (d−1) × hunterEvery,因此占据该格的最早相对时刻是 (d−1)×hunterEvery;玩家每 tick 动一格,推测路径上第 s 步的格子相对占据时刻是 s−1。伤害只比较结算后的最终格,于是"同格伤害"的充要条件是:追逐者在该结算时刻不晚于玩家到达并停留,或恰好同时到达。

2.3 蹲守钥匙
出口蹲守无效(成功结算优先),但钥匙是强制必经点:玩家拾取钥匙必须踩上钥匙格。因此:

玩家无钥匙时,距钥匙最近的追逐者若满足 (d−1)×hunterEvery ≤ pDist[key] − 2(至少提前约 1 tick,余量吸收闸门延误),就直接以钥匙格为目标驻守;
到位后 tD[hCell] = 0,梯度无更优方向,自然原地等待(wait);
玩家踩上来拾取即同格扣血。玩家唯一的无损解是先踩机关换取 3 tick 无敌帧再拾取,但机关本身也扣 1 血,收益等价——蹲守至少保证 1 次伤害;
若玩家干脆不来拿钥匙,其分数上限被压到 2000,蹲守同样达到目的;
玩家持钥后 hasKey 为真,蹲守自动解散,转入拦截/直追。
2.4 路径拦截与直追
拦截:沿推测路径从近到远(第 r 个非蹲守追逐者从第 1+2r 步开始,避免扎堆)找第一个满足"我的相对到达时刻 ≤ 玩家的相对到达时刻"的格子,提前占位等待玩家经过。出口格本身跳过(拦截无意义)。
直追:拦不到(玩家通常更快)时以玩家当前格为目标做 BFS 梯度下降。它抓不到理性逃跑的玩家,但持续施压能侵蚀对方的速度分,并等待对方在死胡同、闸门等待、贪币绕行时犯错。
2.5 走子
对目标格做一次 BFS 得距离场,在 4 个邻格中选"当前 tick 未被关闭闸门阻挡且使距离严格下降"的方向(平局按 up/right/down/left 固定序);站在关闭闸门上向外走不受影响;全被挡则 wait。每次 decide 的目标距离场用 Map 去重(多个追逐者同目标时只算一次)。

2.6 状态记忆
无跨决策状态:每次调用从观测全量重算(总开销远低于预算,见第 4 节),不依赖 memory,不存在状态漂移;同样天然满足"每个玩家世界里的追逐策略独立 memory"的要求。

3. 状态记忆与确定性
strategy.js:

重状态(闸门/机关查找表、环格、树深、可复用类型数组缓冲)放在 Worker 顶层变量,协议明确允许其跨决策保留;
不返回 memory(字段省略,下次收到 null):缓存是几百 KB 的类型数组,序列化进 32KB 的 memory 既放不下也徒增每 tick 开销;观测每 tick 都带完整世界副本,顶层缓存按 seed+尺寸 校验,不符即重建,重初始化安全;
轻状态只有 COMMIT(晶片迟滞)与 COINS_SEEN,均可由观测重建。
hunter.js:完全无状态。

确定性:两份代码不含任何随机源与时钟;平局一律按固定方向序(up/right/down/left)与格子编号序打破。同种子、同名单、同顺序的重赛可精确复现。播放速度、Worker 调度等环境因素不影响决策内容(纯同步函数,输入相同则输出相同)。

4. 复杂度分析(理论估计,非实测)
记 N = W×H ≤ 875(expert 35×25),E ≤ 4N,H = 220(前瞻层数)。

初始化(每局一次):

环格判定 O(N·(N+E)) ≈ 数百万次基本数组操作;
其余(度数、树深、查找表)O(N)。现代 JS 引擎上为毫秒级,远低于 1500ms 初始化预算。
strategy.js 每 tick:

步骤	复杂度
追逐者威胁场 BFS	O(N+E)
时间展开 BFS	每层 ≤ N 个状态 × 5 个选项;实际层数 ≤ min(220, 锚点到达层+40, 剩余 tick),典型几十到一百余层
锚点静态 BFS	O(N+E)
目标选择	O(晶片数)(≤ 16)
最坏情形(锚点被封死,连续三级松弛)原本约为 3 × 220 × 875 × 5 ≈ 2.9×10^6 次选项检查;有了停滞提前终止,不可达锚点的饱和搜索在约 40-60 层后即被截断,实测单次 decide 最慢耗时降至预算的 1/3 左右。常规情形只跑一次且提前收敛。内存方面最大的一次性分配是时间 BFS 的父指针数组 Int32Array(N×222) ≈ 0.78MB(expert),其余缓冲更小。

hunter.js 每次调用:2 + 猎手数 + 去重后目标数 次 BFS,≤ 9 × O(N+E),加一次路径重建 O(N),毫秒级;每次调用临时分配 ≤ 约 9 组 Int16Array+Int32Array(共约 40KB),对 GC 压力可忽略。

以上为基于数据结构的量级推导,另在本地自建 Node 模拟器上做过非官方自测(非官方环境,仅供参考):三种难度各 12 局、追逐方为本仓库 hunter.js 时全部逃出;换朴素直追对手共 90 局中约 93% 逃出;单次 decide 观测到的最慢耗时约为预算的 1/3(scout 23ms / standard 45ms / expert 70ms);同种子重复运行动作序列一致。这些数字来自自建模拟器,不代表官方环境成绩。

5. 局限与设计取舍
序贯贪心而非 TSP:晶片路线没有做全局最优(如 2-opt),而是每 tick 重评估的贪心 + 迟滞。理由:追逐者位置动态变化使全局路线每 tick 都会失效,重规划的鲁棒性比离线最优更重要;且 detour ≤ 预算 的约束让解空间很小。代价:极端地图上可能比最优顺序多花 10–20 tick,折合约 50–100 分速度分。
追逐者建模是单步快照:威胁场假设追逐者保持当前位置,到达时刻用 (d−1)×hunterEvery 近似(忽略"本 tick 是否恰逢其行动 tick"的相位差,误差 ≤ hunterEvery−1 个 tick,靠 slack=2 的余量与每 tick 重规划吸收)。没有做博弈搜索(对手策略未知且每轮随机抽取),以"规避 + 重规划 + 逃避模式"的鲁棒性代替最优博弈。被多个追逐者钳形夹击且身处深树状分支时仍可能无解——协议明言不保证玩家必胜。
逃避是 1 步贪心:只看下一格的评分,没有多步逃逸路线规划。多数情况够用(速度优势 + 树深惩罚防死胡同),但复杂的夹击场面下不如小型博弈搜索精细。
1 血 + 钥匙被蹲守:选择不自杀,转为安全收集(超时上限 2000 分,保住 HP 分);若剩余时间 < 30 tick 或血量 ≥ 2 则强行取钥。这是"必死之局最小化损失"的取舍。
未利用机关无敌帧战术:先踩激活机关获得 3 tick 无敌,再穿越追逐者或踩蹲守的钥匙格。适用窗口太窄(无敌仅 2 个有效 tick)、需要精确的相位规划,收益场景少,故未实现。
hunter 的路径预测是"玩家走最短路"假设:聪明玩家会绕开被占的拦截点,拦截随之落空并退化为直追;直追对理性玩家基本无效,真实价值在于施压与针对次优走位。蹲守钥匙是唯一"必然命中一次"的机制,代价是这名追逐者离开追击序列。
hunter 不做追逐者间的占位协调(可重叠、可同格),只通过"路径位置错位 + 蹲守独占"做松散分工;也不针对特定对手风格建模(对手每轮随机抽取,信息不可得)。
探索分完全顺带:没有为 500 分的探索分做专门规划(visited 去重格数 / 通道总数),路径与晶片绕行自然覆盖的即是所得。若要压榨可加"绕新路"微偏好,但会与速度分/安全冲突。
闸门 LUT 信任观测参数:period/on/phase 直接来自观测而非硬编码 2/6–8,协议若调整周期范围无需改代码;但若出现 period ≤ 0 的非法数据会钳制为 1(视为常开/常激活),这是防御式处理。
