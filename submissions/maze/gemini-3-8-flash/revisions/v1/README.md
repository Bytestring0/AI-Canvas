# 迷宫竞速：AI 策略设计与算法说明文档

本项目包含两个独立且确定性的自主决策智能体实现：
- `strategy.js`：跑者（Runner）逃生与巡航策略。
- `hunter.js`：追逐者（Hunter）协同封堵与围剿策略。

---

## 一、走迷宫策略设计 (`strategy.js`)

### 1. 核心算法体系
跑者策略以**通关逃生为最高优先级（6000分基石）**，兼顾**通关耗时惩罚与晶片探索附加分**。算法由三层架构驱动：

1. **时空周期感知与危险场建模 (Spacetime Hazard Modeling)**：
   - 传统寻路易在“开启的机关”或“已到来的追逐者”面前猝死。
   - 算法通过 `(tick + phase) % period < on` 显式预测未来时间步 $t+1$ 的闸门开启状态与机关激活情况。
   - 追逐者威胁度建模：结合全局多源 BFS 距离场与 `hunterEvery` 步频节奏，评估各追逐者到达候选格子的时间。若在无敌保护帧 (`invulnerableUntil`) 之外可能与追逐者同格或踩入激活机关，施加极高排斥惩罚（`+20000`）。

2. **多目标贪心收益评估 (Opportunistic Chip Collection)**：
   - 全局主目标为动态设定：当未获得钥匙时为主目标 `key`，拿到后自动切换为 `exit`。
   - 针对地图中的晶片 `coins`，计算其相对于主路径的偏航代价 $\Delta d = (d(player, coin) + d(coin, target)) - d(player, target)$。
   - 仅当 $\Delta d \le 4$ 步且追逐者抵达晶片的时间裕度充足（安全窗口）时，才切换阶段目标为就近晶片；杜绝因贪晶片导致的死亡或高耗时得不偿失。

3. **拓扑防死胡同评分机制 (Dead-End Detection)**：
   - 在追逐者接近时（距离 $\le 4$），算法评估候选格的通道出度（连通邻格数）。若进入只有单个出路的死胡同且被追逐者堵截，施加惩罚，迫使智能体优先向环路和宽阔交叉口机动。

### 2. 状态记忆与确定性破局
- 通过 `observation.memory` 记录上一次所处坐标 `lastPos` 及滞留计数 `stuckCount`。
- 若因闸门周期或追逐者逼近导致在原地等待连续达到 3 个 tick，自动触发破局逻辑：在次优但安全的候选分支中尝试横向机动，避免局部震荡死锁。

## 二、追逐策略设计 (`hunter.js`)

### 1. 协同追捕战术 (Multi-Hunter Coordination)
追逐者仅在 `(tick + 1) % hunterEvery === 0` 时行动。为防止多追逐者追击同一路径导致互相重叠并被玩家“一溜多”，采用**角色分工协同机制**：

1. **主追者（Hunter 0 - Direct Chaser）**：
   - 始终以玩家当前瞬时坐标为目标，沿考虑当前闸门启闭状态的 BFS 最短路径实施全速逼近，迫使玩家不断消耗机动空间。
2. **要道截断者（Hunter 1 - Interceptor）**：
   - 预判玩家下一阶段的核心逃生目标（未拿钥匙则为钥匙，已拿钥匙则为出口）。
   - 计算玩家与目标之间的战略中点或直接设防于目标点前，实现迎头拦截与关门合围。
3. **侧翼包抄者（Hunter 2+ - Flanker）**：
   - 计算玩家周围 2 格范围内的各向分支通道，选择远离 0 号追逐者的反向交叉路口作为伏击点，封锁玩家变向迂回的退路。

### 2. 动态环境适应与鲁棒性
- 追逐者行动受限于当前 tick 的闸门状态。BFS 搜索在首步展开时强制过滤当前关闭的闸门，避免撞门浪费步数；若目标路径被闭合闸门完全阻断，自动降级为曼哈顿局部逼近，保持对玩家的压迫姿态。

## 三、复杂度与资源考量

| 策略            | 时间复杂度 (每次决策)                            | 空间复杂度                          | 说明                                                                                                                 |
| :-------------- | :----------------------------------------------- | :---------------------------------- | :------------------------------------------------------------------------------------------------------------------- |
| **strategy.js** | $O(V + E)$，其中 $V \le 875, E \le 3500$         | $O(V)$ 固定类型数组（约数十 KB）    | 迷宫规模最大为 35×25。单次运行 2~4 次轻量 BFS 仅耗时 1~3ms，远低于 200ms 的阈值。使用扁平 `Int16Array` 避免频繁 GC。 |
| **hunter.js**   | $O(K \times (V + E))$，其中 $K \le 3$ 为追逐者数 | $O(V)$ 类型数组（复用单次搜索空间） | 最多执行 3 次单源 BFS，耗时通常在 2ms 以内，无内存泄露风险。                                                         |

## 四、局限性与设计取舍

1. **全周期时空 A\* vs 单步距离场剪枝**：
   - *取舍*：在 800 ticks 的长期时空图上展开完整的 Space-Time A\* 搜索能够找到理论绝对全局解，但在多移动实体和周期闸门耦合下分支系数极大，存在极端情况下单帧计算超时的风险。因此本方案选取“全图静态/阶段距离场 + 前瞻 1 步危险阻断 + 宏观安全裕度”的混合架构，在确保极致响应速度的前提下保持高效避险。
2. **擦肩无伤（Pass-through）机制利用**：
   - 规则明确“双方交换位置不造成伤害”。然而依赖擦肩属于高风险操作，一旦目标格也是机关或遇后续追逐者同格则直接掉血。本策略选择保守规避同格碰撞，确保生存率。
3. **晶片探索取舍**：
   - 探索分（最多 500 分）与晶片分（最多 1000 分）虽然诱人，但速度分（最多 2000 分）随耗时增加线性递减。大幅度绕路搜集晶片往往使速度得分折损超过晶片收益本身，故本策略将晶片严格限制在“微小偏航（$\le 4$ 格）”时才执行顺路搜集。
