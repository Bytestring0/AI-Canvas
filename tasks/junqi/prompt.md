# 将军棋：AI 策略编程任务（完整独立协议 junqi-2）

你无法访问仓库、网页、SDK 或其他文件。下面包含全部协议，请直接完成代码，不要索要其他资料。

请交付且仅交付两个完整文件：

1. `strategy.js`：将军棋策略。
2. `README.md`：解释算法、状态记忆、复杂度、局限与设计取舍，不虚构实测结果。

回答时用两个带文件名的代码块给出全文。`strategy.js` 必须在顶层定义 `function decide(observation) { ... }`；可以增加函数、常量。不要使用 import、export、第三方包或依赖外部文件。可用 TypeScript 设计，但交付必须是编译后的标准 JavaScript，不含类型标注。

游戏是多玩家同时进行的征服类对战（规则参照 generals.io）：地图上有山地、中立城市和每名玩家的将军；视野有战争迷雾；每 tick 结算一次移动与战斗；攻陷敌方将军即令其出局并接收其领土。

## 运行方式与资源

纯现代浏览器，无后端、无 AI API 调用。每名参赛者的策略在独立 Web Worker 执行，Worker 位于不透明源 sandbox iframe 内，CSP 禁止联网，无法访问页面、父窗口和存储。不得使用网络、DOM、动态模块、importScripts 或额外 Worker。初始化最多 3000ms；每次 decide 的自身执行（包含其内部异步等待）最多 1000ms，超时直接终止。时限在沙箱内按策略执行时间计量，消息传递与页面渲染延迟不计入。文件不超过 100000 字节；每次返回值 JSON 序列化后最多 32768 字符，所有数字必须有限，不得使用循环引用、BigInt 或不可序列化状态。推荐同步、快速的算法；1000ms 是硬性淘汰线而非目标，常规决策应远低于此值。

策略可返回 memory（任意 JSON 值），下次调用通过 observation.memory 原样收到；不返回则重置为 null。每局每个 Worker 独立初始化，顶层变量可跨决策保留，但不得依赖 Date、performance、Math.random、crypto 等非确定性输入；需要随机时用 seed、tick 和自建确定性伪随机生成器。同一地图种子、名单和确定性脚本应可重赛复现。播放速度仅影响展示时间，不能影响决策。脚本不会得知对手名称或源码，也不知道对手用的是哪份代码。

## 地图与对局

地图由种子生成。`terrain[y][x]`：`-1` 从未侦察（迷雾），`0` 空地，`1` 山地（不可进入），`2` 城市，`3` 将军。坐标从左上角 (0,0) 开始，x 向右、y 向下，边缘一圈是山地。全部可通行格子互相连通。每局 2~16 名玩家；自由混战每人一队，或 2~4 队组队。将军和己方城市每 tick 产兵；普通己方土地每 25 tick 产兵。单次产量从 1 军开始，每 200 tick 增加 1 军，精确公式见结算顺序第 7 条。中立城市驻军 40~50 且不再增长。对局最多 maxTicks tick（场地决定，800/1200/1600），到时以军力优势判胜。

场地与人数决定地图（宽×高）：

| 场地 | 尺寸 | maxTicks | 中立城市数 |
| --- | --- | --- | --- |
| 紧凑 | (7+2N)×(6+2N) | 800 | 2N+2 |
| 标准 | (8+2N)×(7+2N) | 1200 | 2N+2 |
| 辽阔 | (11+3N)×(10+3N) | 1600 | 4N+4 |

N 为玩家数。将军初始 1 军，位置由种子确定且互相远离；中立城市距将军较远。

### 战争迷雾

你的视野是所有己方格子的 8 邻域（含斜角）并集。`terrain` 一旦侦察过就保持已知（山地、城市、将军的位置会记住，敌方将军被见过后位置一直标记）；`owner` 与 `army` 只在当前可见时给出，视野外为未知。请把长期信息存进自己的 memory。

## 统一输入

每个 tick 调用一次 `decide(o)`，o 结构如下。输入是对局状态的副本，修改它不会影响环境。

```ts
type Move = {from: {x: number, y: number}, dir: 'up'|'right'|'down'|'left', half?: boolean};
interface Observation {
  version: 'junqi-2';
  role: 'player';
  seed: string;        // 地图种子
  tick: number;        // 当前 tick，从 0 开始
  maxTicks: number;
  width: number;
  height: number;
  playerCount: number; // 2~16
  you: {id: number, team: number, general: {x: number, y: number}, alive: boolean};
  players: {id: number, team: number, alive: boolean, army: number, land: number}[]; // 全员公开的总军力与领土
  terrain: number[][]; // -1 未知 / 0 空地 / 1 山地 / 2 城市 / 3 将军（见迷雾规则）
  owner: number[][];   // -2 视野外未知 / -1 中立 / 0..playerCount-1 玩家 id（仅当前可见）
  army: number[][];    // -1 视野外未知，否则该格军队数（仅当前可见）
  memory: any;         // 上次返回的 memory，首次为 null
}
```

## 输出与有效示例

每次必须返回 `{moves: Move[], memory?: JSON}`。每 tick 最多 4 条移动，按数组顺序依次结算；同一 tick 内前一指令的结果对后续指令可见。`half` 省略或为 true 时移动 `floor(军队数/2)`；`half: false` 移动全部减 1。只有己方且军队 ≥2 的格子可以出发；方向必须相邻合法。非法的移动（不属于己方、军队不足、出界、撞山地）会被忽略，不是错误；但返回格式非法（缺 moves 数组、字段类型错误、超过 4 条等）会判策略错误出局。可以返回空 moves 表示待命。示例：

```javascript
function decide(o) {
  // 找到己方军队最多的格子，向第一个可进入的方向移动一半军队
  let best = null, bestArmy = 1;
  for (let y = 0; y < o.height; y++) for (let x = 0; x < o.width; x++) {
    if (o.owner[y][x] === o.you.id && o.army[y][x] > bestArmy) {bestArmy = o.army[y][x]; best = {x, y}}
  }
  if (!best) return {moves: [], memory: null};
  const dirs = [['up', 0, -1], ['right', 1, 0], ['down', 0, 1], ['left', -1, 0]];
  for (const [dir, dx, dy] of dirs) {
    const terrain = o.terrain[best.y + dy]?.[best.x + dx];
    if (terrain === 0 || terrain === 2 || terrain === 3) {
      return {moves: [{from: best, dir, half: true}], memory: null};
    }
  }
  return {moves: [], memory: null};
}
```

## 精确结算顺序

1. 当前 tick t：每名存活玩家收到 tick 开始时的完整观察（各自视野），同时决策，互不可见他人的指令。
2. 策略返回格式非法、执行异常或超时的玩家立即出局：其所有格子变为中立（军队保留，将军变为中立城市），不执行其指令；对局继续。
3. 依次结算各玩家的指令，玩家行动顺序按 `(tick + i) mod 玩家数` 轮转（每 tick 轮换先手，先后仅影响同 tick 竞争同一格的结果）。每名玩家最多执行 4 条，按提交顺序逐条结算。
4. 单条移动：从 from 格减去 k（half: k = floor(n/2)，否则 k = n-1，n 为出发格军队，k ≥ 1）。目标格为山地或出界则忽略；目标是己方或同队队友的格子则 k 直接加入该格（增援，不改变归属），随后指令可继续从新位置出发。
5. 目标是敌方或中立格子则发生战斗：k 大于守军时攻占该格，留下 k − 守军 军队；k 不大于守军时进攻方全军覆没，守方剩下 守军 − k 军（可以为 0，但格子仍归守方）。
6. 被攻陷的格子若是敌方将军：该玩家立即出局，其全部格子（含将军格）转让给进攻方，每格军队减半（floor，至少 1）；将军格地形变为城市，进攻方本次的剩余军队 k − 守军 再并入该格。击杀数记给进攻方。中立城市只是普通高驻军格子。
7. 全部指令结算后进入生产阶段：本阶段产量 `g = 1 + floor(tick / 200)`（tick 是推进前的输入 tick）。己方将军与己方城市每 tick 各 +g 军；己方普通土地在 `(tick + 1) % 25 === 0` 时各 +g 军。完成第 1~200 tick 时产量为 1，第 201~400 tick 为 2，以此类推。中立格子不生产。
8. tick 推进到 t+1。当存活队伍只剩 1 队（自由混战即最后一人）时对局结束；若双方同 tick 内互攻将军，按第 3 步的轮转顺序先后结算，被攻陷的一方立即出局，不再执行其后续指令，因此不会同归于尽。tick 达到 maxTicks 仍未分出胜负时，以各队总军力（平局看总领土）判胜。

## 计分与排名

每名玩家满分 10000，各项向下取整，对局中实时更新：

- 胜利：所在队伍获胜得 4000（含回合用尽判胜），否则 0。策略错误出局的玩家总分为 0。
- 击杀：`floor(1500 × 击杀敌方将军数 / 敌方玩家数)`，敌方玩家数至少为 1。
- 领土：`floor(2000 × 己方土地格数 / 全体玩家已占土地总数)`（分母至少 1），避免大地图中立空地过多压低成绩。
- 军力：`floor(2000 × 己方总军队 / 全体玩家总军队)`（分母至少 1）。
- 存活：`floor(500 × min(存活 tick 数, 当前已运行 tick 数) / max(1, 当前已运行 tick 数))`。存活到结束得 500，提前出局按实际对局时长折算，避免快速结束的对局被 maxTicks 压低分数；tick=0 时此项为 0。

排名按总分降序；同分时存活者优先，再比领土、军力，最后按玩家 id 稳定排序。排行榜会跨多局累计积分。
