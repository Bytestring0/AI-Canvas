# 将军棋

参照 generals.io 规则的多人征服对战，纯前端策略竞技任务，可随站点部署到 GitHub Pages。地图生成、战争迷雾、战斗结算、排行榜与真人下场全部在浏览器完成，不需要后端或模型 API。项目的 Python 只负责现有静态站点构建。

## 给 AI 的任务

在任务页点击右上角「任务说明」，切换到「AI 完整提示词」，完整复制给各个外部 AI。规则与说明统一在此弹窗中查看；完整独立协议保存在本任务 `prompt.md`，包括全部输入输出字段、结算顺序与计分。外部 AI 不需要访问仓库。

每个 AI 仅交付两个文件：

- `strategy.js`：定义顶层 `function decide(observation)`，每 tick 返回最多 4 条移动指令与可选 memory。
- `README.md`：算法与战术说明。

脚本不用模块语法、依赖包、网络或 DOM。TypeScript 请先编译成标准 JavaScript 再交付。

## 对局规则速览

- 每名玩家一座将军；将军和己方城市每 tick 产兵，普通土地每 25 tick 产兵。每次产量为 `1 + floor(tick / 200)`：前 200 tick 每次 +1，第 201~400 tick 每次 +2，后续持续增加；中立城市驻军 40~50，不生产。
- 以 4 人为例，紧凑 / 标准 / 辽阔地图分别为 15×14、16×15、23×22，中立城市分别为 10、10、20 座。
- 视野为己方格子的 8 邻域；地形侦察过后保持已知，归属与军队只在视野内可见。
- 移动从己方 ≥2 军的格子出发：`half: true`（默认）走 floor(n/2)，`half: false` 走 n−1；可增援队友，攻入敌/中立格按军力相减。
- 攻陷敌方将军：对方出局，全部领土减半转让，将军格变为城市。策略错误/超时同样出局，领土变为中立。
- 同 tick 指令按 `(tick+i) mod 人数` 轮转先后；全部对局最多 800/1200/1600 tick（按场地），到时按军力判胜。

## 网页玩法

- **名单**：正式提交、本地导入（localStorage，最多 12 个）与内置基准「基准机器人」全部可勾选；「随机抽签」按人数从策略池随机抽取，「全部参赛」一键勾满，也可以逐个手选。
- **模式**：「自由混战」各自一队；「组队作战」可手动指定甲/乙/丙/丁队或「随机组队」（2~4 队自动平衡），同队互相增援不交战。2~16 人（含真人）。
- **真人下场**：「＋ 加入真人」最多添加一位真人，添加后入口禁用，移除后可重新添加。点击己方格子选中并默认带走全部军队（留 1 军），双击改为带走一半，点相邻格或按 WASD / 方向键移动。默认开启真人迷雾视角，无真人时使用上帝视角。
- **实时记分**：右侧排行榜每 tick 刷新军力、领土、城市与得分（胜利 4000 + 击杀 1500 + 领土 2000 + 军力 2000 + 存活 500，满分 10000）；战况事件流记录占城、擒王与出局。
- **计分口径**：领土分按全体玩家已占土地中的份额计算，军力分按玩家军力份额计算，存活分按实际已运行时长折算。这样大图的中立空地和快速结束对局不会额外压分。新规则为 `junqi-2`，战绩使用独立存储，不混入旧规则成绩。
- **回放**：时间轴可暂停并回看任意 tick；「同图重赛」用相同名单与种子复现整局，验证策略确定性。
- **战绩排行榜**：每完成一局自动累计各参赛者（含真人与基准）的局数、胜场、击杀与总积分，保存在当前浏览器，可一键清空。注意不同人数/场地之间场均分不可直接比较。
- **导出**：可导出本局 JSON（名单、源码、逐 tick 事件与结算），方便复盘。

内置基准「基准机器人」故意写得很弱：只从军队最多的格子按固定方向轮转移动半军，不认路、不打城市、不找将军、不防守，仅作为接口示例和最低参照，不冒充模型作品。

## 隔离和异常

每个策略放在独立的可终止 Worker 中，Worker 由 `sandbox="allow-scripts"`、无同源权限的 iframe 创建，继承禁止联网的 CSP，无法访问站点 DOM 或本地存储。初始化时限 3000ms，每次决策时限 1000ms（按策略自身执行时间在沙箱内计量，消息链路与渲染延迟不计入，另设 8 秒送达兜底）；每份脚本最多 100000 字节，输出 JSON 最多 32768 字符。策略返回格式非法、执行异常或超时的玩家立即出局，领土变为中立，其余玩家继续。此隔离用于浏览器内运行，不是防作弊或跨设备权威成绩服务。

请编写确定性策略：同一种子、名单与顺序应复现相同对局；不要依赖系统时间或无种子的随机数。

## 正式收录

把两个文件直接保存到模型目录，目录名就是页面显示的模型名，无需注册或 submission.json：

```text
submissions/junqi/你的模型名/
  strategy.js
  README.md
```

已有 `revisions/v1/` 结构也会自动识别。保存后执行 `python -m canvas build` 并刷新，或 `python -m canvas serve` 本地预览。构建从不执行参赛脚本。此任务没有周期调度。

## 测试

- `npm run test:junqi`（Node 20+）：覆盖地图生成与连通性、将军间距、移动与战斗数值、擒王转让、错误出局、生产节奏、迷雾观察、计分边界，以及基准对基准在 2 人 / 4 人 / 2v2 的完整对局可复现性。
- `python -m unittest discover -s tasks/junqi/tests -p "test_*.py"`：验证任务插件契约（提示词自包含、提交文件与大小限制）。
- `npm run test:junqi:browser`：已构建并启动站点、安装 Playwright 后，验证真人限制、对局推进、回放与策略异常处理。可通过 `JUNQI_BASE_URL`、`JUNQI_PLAYWRIGHT_MODULE` 和 `JUNQI_BROWSER_PATH` 指定测试环境。
