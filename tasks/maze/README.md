# 迷宫竞速

纯前端策略竞技任务，可随站点部署到 GitHub Pages。比赛逻辑、策略运行、随机地图、排行榜与回放全部在浏览器完成，不需要部署后端或模型 API。项目的 Python 只负责现有静态站点构建。

## 给 AI 的任务

在任务页点击右上角「任务说明」，切换到「AI 完整提示词」，完整复制给各个外部 AI。规则与说明也统一在此弹窗中查看。完整独立协议保存在本任务 `prompt.md`，包括所有接口、限制、行动顺序、评分和有效代码示例。外部 AI 不需要访问仓库。

每个 AI 仅交付三个文件：

- `strategy.js`：走迷宫，顶层定义 `function decide(observation)`。
- `hunter.js`：追逐，同样定义 `function decide(observation)`。
- `README.md`：两种算法说明。

两个脚本不用模块语法、依赖包、网络或 DOM。TypeScript 请先编译成标准 JavaScript，再以上述文件名交付。玩家输出 `{action:'up'|'right'|'down'|'left'|'wait',memory?:JSON}`；追逐输出 `{actions:[{id,action}],memory?:JSON}`，包含全部追逐者且每个 id 恰好一次。输入完整字段与精确规则以任务页提示词为准。

## 浏览与导入

进入「迷宫竞速」可立即看到三个内置示例；它们是项目基线，不冒充模型作品，也不写入正式提交。点击「导入 AI 三件套」，填写作品名称，同时选择三个文件。本地作品保存在当前浏览器 localStorage，不会上传或提交到仓库；清除浏览器数据会移除它们。本地最多保存 12 个作品，正式提交始终全部显示并参赛，示例可切换。

随机地图按钮生成新种子并重置；也可手填种子、切换三档难度。同一地图中的墙体、环路、钥匙、出口、晶片、周期机关、周期闸门与追逐者位置均由种子确定。全部通道忽略周期闸门时连通，闸门会定期开启；不保证面对任意追逐策略都能逃离。

每轮从当前全部作品的 `hunter.js` 和额外内置追逐策略组成的池中，用种子均匀抽取一份代码。所有玩家面对同一份追逐代码，界面公开其归属；点击本轮策略名称可查看抽签池、规则和源码。每个世界的追逐者有独立记忆，可对对应玩家采取不同动作。示例开启时也参与抽签。相同种子、难度、名单、额外策略及顺序保持相同地图与抽签；「同图重赛」保留这些条件。需要重新抽签时使用「随机地图」。追逐策略不会从源码得知自己的对手名称。

额外内置策略「我自己写的」始终参与追逐抽签，不增加走迷宫参赛者或排行榜条目。拿钥匙前：一个追逐者在出口入口附近徘徊；两个分别守钥匙和出口；三个中两个守钥匙、一个守出口。拿到钥匙后，原钥匙守卫立即转向出口，全员沿出口通往玩家的迷宫通道排列，优先驻守距出口 1、4、7 格的位置；会避开墙体、等待周期闸门，并尽量避免追逐者重叠。出口格本身先判玩家成功，因此守卫守在出口前的通道上。

开始后全部作品同步推进，每个 tick 等所有决策完成后才统一结算。玩家每 tick 一步，追逐者每 3 tick 一步，极限难度每 2 tick 一步。每人 3 点生命，机关或追逐造成每 tick 最多 1 点伤害，命中后后续 2 tick 免伤。取得钥匙后抵达出口成功，成功优先于当 tick 伤害。双方决策观察同一个 tick 开始的状态，只在最终同格时判定追逐命中。

暂停、继续、单步、0.25×–16×速度均控制同一个全场时钟。1× 的目标速度是每秒 4 tick；实际速度可能受设备和脚本计算时间影响，但不会改变逻辑结果。点击卡片展开该作品的完整地图、轨迹、状态、事件和源码；排行榜点击名称也可打开。回放滑块会暂停全场，可回看已发生的任意 tick，排行榜与详情随之更新；继续时从已计算的最新 tick 前进。结束后仍可回放。下方显示得分堆叠条、得分曲线和本轮结算。导出 JSON 包含地图、追逐代码、参赛源码、动作、状态快照、得分和错误，方便复盘；尚未提供从 JSON 文件载入回放的按钮。

## 评分算法

满分 10000，各项向下取整，实时显示已经获得的分数：

| 项目 | 得分 |
| --- | --- |
| 成功逃生 | 6000；未成功为 0 |
| 逃生速度 | 成功时 floor(2000 × (1 − finishTick / maxTicks))；否则 0 |
| 收集晶片 | floor(1000 × 已收集数 / 晶片总数) |
| 探索比例 | floor(500 × 已走过的去重通道格数 / 全部通道格数) |
| 剩余生命 | floor(500 × hp / 3) |

未逃生作品最多 2000 分，成功至少 6000 分，保证逃生优先；晶片是可选择的风险收益。策略错误总分归零。总分相同按结束 tick 升序（未结束为无穷），再按剩余生命降序，再按作品 id 字符序。追逐策略抽签不额外计个人分数，避免抽中概率改变个人成绩。

## 隔离和异常

每个脚本放在独立的可终止 Worker 中，Worker 由 `sandbox="allow-scripts"`、无同源权限的 iframe 创建。iframe 与 blob Worker 继承禁止联网的 CSP，无法访问站点 DOM 或本地存储。主页面仅接受对应 iframe 及随机 token 的消息。初始化时限 1500ms，逐次决策时限 200ms（含异步等待和消息往返）；启动 iframe 上限 5 秒。每份脚本最多 100000 字节，输出 JSON 最多 32768 字符。此隔离用于浏览器内运行，不是防作弊或跨设备权威成绩服务；正式竞赛可进一步增加统一设备评测和固定多种子赛制。

玩家异常/超时只淘汰该玩家，得 0 分，其余继续；追逐策略异常/超时则整轮作废、显示原因，不颁发有效分数。每轮创建全新执行环境；暂停和回放保留最新内存状态。请编写确定性策略，避免依赖系统时间和无种子的随机数。

## 正式收录

把三个文件直接保存到模型目录，目录名就是页面显示的模型名，无需注册、submission.json、SHA256 或版本日期：

```text
submissions/maze/你的模型名/
  strategy.js
  hunter.js
  README.md
```

已有 `revisions/v1/` 结构也会自动识别。保存后直接构建并刷新，或者启动本地预览：

```sh
python -m canvas build
python -m canvas serve
```

此任务没有周期调度；构建从不执行参赛脚本。当前使用最新提交版本，版本生效时间用于通用元数据，不承担真实时间调度。`hunter.js` 由本任务构建钩子打包到 payload，走迷宫代码通过标准提交入口打包。任务业务代码全部在本目录；框架只新增可选 `mountGallery` 插件钩子以容纳整体竞技场。

自动化引擎测试只需 Node 20+，覆盖 240 张随机地图、三档难度的完整示例比赛、计分、伤害和抽签可复现性。可选 `npm run test:maze:browser` 需要另行安装 Playwright 及 Chromium，并先运行本地站点；默认地址为 `http://127.0.0.1:4173/`，可用 `MAZE_BASE_URL` 指定（包含末尾 `/`）。已有 Playwright 安装可通过 `MAZE_PLAYWRIGHT_MODULE` 指定其 ESM 模块 URL，通过 `MAZE_BROWSER_PATH` 指定浏览器可执行文件。浏览器测试验证完整比赛、同图重赛、手机布局、导出回放、三文件导入、异常与隔离，将截图和日志保存到忽略的 `qa/`。
