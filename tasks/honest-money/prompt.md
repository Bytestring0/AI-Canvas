## 四、标准输入的完整结构

输入是 UTF-8 JSON 对象，包含以下字段：

- `schema_version`：整数 2，表示本协议。
- `slot`：本轮计划的 10 分钟槽位，带时区 ISO 8601 时间戳，如 `2026-10-19T09:40:00+08:00`。
- `as_of`：本轮真实采集时刻，同样带时区；它可能晚于 slot。history 不包含晚于 as_of 的采集记录。
- `execution`：固定为 `next_observed_fresh_quote`，意思是本次输出的订单只在之后的一次新报价上尝试成交。
- `revision`：当前策略版本字符串，例如 v1、v2；只用于识别版本与迁移 memory，不要假定始终为 v1。
- `environment`：上一节给出的完整参数对象。
- `account`：本轮旧委托已结算、费用和利息已计算、持仓已估值后的权威账户状态，结构见下文。
- `history`：按时间升序排列的实际报价快照数组，包含当前快照，最多 240 条；启动初期可能只有一条，不能假定具备任何最短历史长度。
- `memory`：上次成功输出时保存的 JSON 对象，首次是 `{}`；新版本也会收到旧版本留下的对象。它与本次输入 account.memory 是同一份内容。

account 的字段：

- `cash`：当前现金，可以为负；债务等于 `max(0, -cash)`。
- `positions`：按股票代码索引的持仓字典，无持仓时为 `{}`。每项包含 `quantity`（持有股数）、`sellable`（当前可卖股数）、`cost`（平均买入成本，CNY/股）、`last_price`（最后有效估值价格）、`quote_time`（行情源报告的该价格时间）。公司行为对账后可能附带 `reconciled_on`，无需依赖它决策。未出现在字典中的代码表示零持仓。
- `pending`：结算后尚待处理的委托数组；在当前调用时通常已被清空，不能把它当成刚输出的委托已成交的证明。
- `memory`：同顶层 memory。
- `last_date`：账户刚处理的交易日期 `YYYY-MM-DD`，当前调用中通常就是 as_of 对应日期。
- `last_timestamp`、`last_slot`：刚处理的真实时刻和槽位，当前调用中通常等于本轮 as_of 和 slot。**它们不是“上一次策略调用时间”**；需要上次时间时自行放入 memory。
- `interest_remainder`：累计未满一分钱的借款利息；环境维护，不要重复扣除。
- `equity`：已结算净资产，等于现金与持仓估值之和。
- `peak`：历史最高净资产；`max_drawdown`：到目前为止的最大回撤比例，0.1 表示 10%。二者已由环境维护。
- `active_revision`：本次正在执行的版本标识。

history 每个快照的字段：

- `schema_version`、`slot`、`as_of`：同含义，属于该历史轮次。
- `date`：交易日期；`source`：`tencent/public-quote`；`volume_unit`：说明成交量为当日累计股数。
- `bars`：股票代码到行情对象的字典，某股可能缺失；缺失不等于价格为零，也不保证所有股票每轮都有报价。
- `unavailable`：缺失或无效代码到原因字符串的字典。程序应容忍缺少该字段；不可把缺失行情补成假价格。

每个 bars[symbol] 包含：

- `price`、`close`：本次采样的最新成交价，二者相同，单位 CNY/股；**不是十分钟后的价格或日终收盘价**。
- `open`：当日开盘价；`high`、`low`：当日截至这次采样的最高、最低价。
- `vol`：当日截至该时刻的累计成交股数；`amount`：当日累计成交额（CNY）。它们不是本轮增量，跨日会重置；只有同日有效采样之间才可考虑做差。
- `quote_time`：行情源报告的报价时间，带时区；它通常略早于采集 as_of，可能在不同股票之间不同。
- `pre_close`：当前交易所提供的前收盘参考价；`reference_close`：公开未复权日线中最近一个早于本日的收盘价。
- `up_limit`、`down_limit`：公开行情源返回的当日涨停价和跌停价，不按百分比猜测。
- 不提供复权因子字段；不要读取或假定存在 adj_factor，也不要自行推测分红送转比例。

这是每约 10 分钟采集一次的**当日累计报价快照**，不是 10 分钟 K 线，不能把相邻快照 open/high/low 当成每个区间的 OHLC。历史可能跨交易日、午休、周末、版本变更与漏采时段。禁止前视、联网补数据或插值后假装在缺失时段成交。

## 五、标准输出的完整结构

stdout 只能有一个合法 JSON 对象，使用以下三个字段：

```json
{
  "orders": [
    {"symbol": "000001.SZ", "side": "buy", "quantity": 100, "reason": "填写实际策略触发原因"}
  ],
  "memory": {"strategy_schema": 1, "observations": 1},
  "commentary": "本轮决策摘要"
}
```

这只是委托格式，不要求按此例买入。没有合法交易信号时用 `"orders": []`，仍可更新 memory 和 commentary。

- `orders` 必填，必须是数组，每轮最多 50 条。每条委托必须包含 symbol、side、quantity，可选 reason。symbol 必须在当前 universe；side 只能是 `buy` 或 `sell`。
- quantity 必须是真正的正整数，不能是布尔值、小数或字符串；必须为 lot_size=100 的整数倍，且不超过 1000000000 股。没有“全部卖出”或“按金额购买”的特殊值，请自己计算股数。
- reason 必须为字符串，最多 1000 个字符。不要自行设置委托价格、订单类型、版本或提交时间；只输出上述四个委托字段。
- memory 可选但建议始终返回 JSON 对象；不返回等同于保存 `{}`，会丢失旧 memory。其默认 `json.dumps(memory)` 序列化后的长度不得超过 65536 个字符；只放必要的小型状态，不无限复制全部 history。不能含集合、datetime 对象、Decimal 对象、NaN 或 Infinity，需转成合法 JSON 基础类型。
- commentary 可选字符串，最多记录前 4000 个字符，请自行保持简短。
- stdout 的 UTF-8 总输出不得超过 1000000 字节；调试信息只写 stderr。退出码应为 0。
- 委托的 revision、signal_as_of、submitted_at 由环境在你运行完后写入。不要伪造更早的提交时间，不要用 stdout 之外的渠道下单，也不能直接修改 cash、positions 或 equity。

## 六、环境怎样执行你的委托

每次真实采样的顺序是：

1. 环境先对旧账户计息，跨交易日期时解锁旧持仓，并处理必要的公司行为对账。
2. 使用当前有效报价，按数组顺序尝试上一轮的 pending 订单；更新现金、费用和持仓。
3. 按当前有效价格估值，然后把以上完整 JSON 输入交给你的新进程。
4. 保存你的输出 orders 为下一轮 pending；保存 memory 供下一次调用。首次调用只产生信号，不会在同一轮成交。

具体规则：

- 新单在**下一次实际采样**尝试一次，且对应股票的 quote_time 必须严格晚于你的真实 submitted_at。即使下一次采样的计划 slot 已更新，若个股仍是旧价，也拒绝成交。报价相对该轮 as_of 的年龄必须在 0–600 秒之间；没有有效报价或累计 vol<=0 时拒单。
- 不补跑没有采样的盘中时段，不保证你看到的当前价格能在之后成交。旧单可以跨午休或隔夜等到下一次实际采样；拒单不自动重试，需要策略未来自行重新决策。
- 买单报价达到涨停价（容差 0.001 CNY）时拒绝买入；卖单报价达到跌停价（同容差）时拒绝卖出。这里是保守采样规则，不模拟真实盘口、排队、部分成交或成交量上限。
- 成交价格：买入 `round(price * 1.0005, 2)`，卖出 `round(price * 0.9995, 2)`，然后夹在 down_limit 和 up_limit 范围内。0.0005 就是 slippage_bps / 10000，若输入参数变化应按输入值估算。
- 成交金额 gross 为价格乘股数，保留两位小数。佣金为 `max(5, gross * 0.0003)`，卖出额外收取 `gross * 0.0005`；总费用保留两位小数。买入扣除 gross 和费用，卖出增加 gross 并扣除费用。最低佣金按每笔算，多笔小单可能明显增加成本。
- 买入可令 cash 为负，但包含费用后的 cash 不能低于 -200000；超限整笔拒绝。没有单独的 borrow/repay API，卖出回款会自动减少负现金。
- 负现金按年化 0.06、两次真实采样之间的自然秒数 / (365 * 86400) 计息，包含夜间、午休和周末。不足一分的利息由环境累积，满分后扣除。利息可能令债务超过原上限，没有强制平仓机制；新增买单仍受债务上限约束。
- T+1 按交易日期计算：当日新买份额不能在当日后续任何一轮卖出；跨到下一个交易日期才解锁。卖出数量不能超过当前 quantity 或 sellable；禁止融券。不能因为又过了 10 分钟就把刚买的股票当成可卖。
- 同一轮多个委托按数组顺序执行，要为前面委托预留现金、债务和可卖份额；不要对同一份 cash 或 sellable 重复使用。卖出旧持仓后买入与买入后再卖出，结果可能不同。
- 当前可卖数量、已成交股数和账户现金以每次输入 account 为准，**上次输出的委托不等于已经成交**。输入没有单独的成交查询接口；需要核对时使用当前账户和你保存的少量 memory，不要虚构查询函数。
- 净资产 equity=现金+持仓估值；缺报价时环境沿用最后有效价格并记录 stale_price。cost 只是平均买入成本，不等于当前市场价格。收益率以统一 initial_cash 计算。允许负净资产，最大回撤可能超过 100%。
- 遇到持仓除权差异，环境可能暂停并等待操作者对账；程序不用自行调整股数、派息或直接修改账户。对账后输入 account 已反映调整，旧数量订单可能被撤销，不要把公司行为误判为你自己的成交。
- 超时、非零退出码、无效 JSON、缺 orders、任意一笔非法委托或超限 memory 会使本次新信号失败，不会撤销环境在调用你之前已经完成的结算。本次没有新委托，原持仓继续保留。请对正常的空持仓、短历史、个股缺失和旧 memory 格式做好处理，避免让可预期情况变成进程异常。

## 七、长期状态、版本更新与交付前自检

1. 只用本文信息就能保存两个文件；程序没有外部项目依赖、网络依赖或未完成占位代码。
